    실습: 우리 채널의 검증 루프¶

    이 페이지에서 배우는 것

    • 영상 대본을 만드는 흐름에 세 겹의 검사를 걸어요: 형식 검사(훅), 빌드 검사(Stop 훅), 내용 검토(검토 에이전트).
    • 검사가 "끝났어요"를 허락하는 문지기가 돼요. 대신 무한 반복을 막는 안전장치가 꼭 필요해요.
    • 검사는 먼저 혼자 돌려 보고, 틀린 경우와 맞는 경우를 모두 시험해요.

    1. 세 겹의 문지기¶

    겹 무엇을 언제 도구
    ① 형식 페이지에 "출처와 기준" 절이 있나 파일을 고칠 때마다 PostToolUse 훅(5.6에서 만든 check-page.sh)
    ② 빌드 사이트가 경고 없이 만들어지나(깨진 링크 포함) Claude가 답을 마치려 할 때 Stop 훅
    ③ 내용 원본에 없는 말을 하지 않나 대본이 저장된 뒤 reviewer 에이전트(5.8)

    ①과 ③은 이미 만들었어요. 이 페이지에서는 ②를 만들어요.

    2. 빌드 검사 스크립트¶

    .claude/hooks/check-build.sh:

    #!/bin/bash
# Claude가 답을 마치려 할 때 사이트가 경고 없이 만들어지는지 확인한다.
INPUT=$(cat)

# 이미 한 번 되돌려 보냈다면 이번에는 멈추게 한다 (무한 반복 방지)
if [ "$(echo "$INPUT" | jq -r '.stop_hook_active')" = "true" ]; then
  exit 0
fi

cd "$CLAUDE_PROJECT_DIR" || exit 0
mkdocs build --strict 1>&2 || exit 2
exit 0

    chmod +x .claude/hooks/check-build.sh

    중요한 점 세 가지예요.

    • --strict: 경고가 하나라도 있으면 실패로 쳐요. 깨진 링크도 경고라서 잡혀요.
    • -q(조용히)를 붙이지 마세요. 이 책을 쓰는 동안 직접 겪은 일인데, mkdocs build --strict -q는 깨진 링크가 있어도 종료 코드가 0으로 나와서 검사가 통과한 것처럼 보였어요. -q 없이 돌리면 같은 경우에 종료 코드 1이 나와요. 검사 도구의 "조용한 모드"가 경고를 숨기지 않는지 꼭 확인하세요.
    • stop_hook_active: 이 훅이 이미 Claude를 되돌려 보낸 뒤라면 두 번째에는 멈추게 해요. 공식 문서도 Stop 훅이 연속 8번 막으면 Claude Code가 개입한다고 하고, 이 값을 확인하라고 안내해요.

    3. 혼자 먼저 시험하기¶

    가짜 입력으로 세 경우를 모두 시험해요(내 사이트 폴더에서).

    export CLAUDE_PROJECT_DIR=$PWD
echo '{"stop_hook_active": false}' | .claude/hooks/check-build.sh; echo "종료 코드: $?"
echo '{"stop_hook_active": true}'  | .claude/hooks/check-build.sh; echo "종료 코드: $?"
    • 깨진 링크가 있을 때 첫 번째는 2(막음), 두 번째는 0(풀어 줌)이 나와야 해요.
    • 문제가 없을 때는 둘 다 0이에요.

    이 책에서도 연습용 사이트에서 같은 흐름을 시험해 봤고, -q가 있으면 의도한 대로 막히지 않는 것을 확인한 뒤 위 스크립트로 고쳤어요.

    4. 등록하기¶

    .claude/settings.json:

    {
  "hooks": {
    "Stop": [
      {
        "hooks": [
          { "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/check-build.sh" }
        ]
      }
    ]
  }
}

    빌드는 몇 초에서 수십 초 걸릴 수 있어요. Stop 훅은 Claude가 답을 마칠 때마다 돌아서 작업이 느려질 수 있어요. 불편하면 이 훅을 끄고, 대신 "끝나기 전에 mkdocs build --strict를 돌리고 출력을 보여 줘"를 부탁에 쓰는 ①단계로 내려가도 돼요.

    10살 눈높이 한 줄 요약

    문지기를 세워서 "검사를 통과해야 끝났다고 말할 수 있어"라고 정해 줘요. 그리고 문지기가 같은 말을 무한히 하지 않게 한 번만 되돌려 보내요.

    ★ 한 걸음 더 (심화)

    훅은 내 컴퓨터 권한으로 돌아가니 5.6의 안전 수칙이 그대로 적용돼요. 이 스크립트는 mkdocs만 실행하지만, 훅 스크립트에 외부 입력을 그대로 쓰는 일은 피해요. 그리고 같은 검증 루프를 한 줄 모드(5.10)에 쓰려면 claude -p에서 훅이 어떻게 돌지(믿음 확인이 없어요)를 먼저 확인해요.

    직접 해보기¶

    1. 위 스크립트를 만들고 세 경우를 혼자 시험해요(깨진 링크를 일부러 하나 넣었다가 지워요).
    2. 등록하고 Claude에게 "docs에 test.md를 만들고 [x](nope.md) 링크를 넣어 줘"라고 시켜요.
    3. Claude가 빌드 오류를 받고 링크를 고치는지 지켜봐요. 고치지 못해도 두 번째에는 멈추는지 확인해요.
    4. 끝나면 test.md를 지우고 훅을 유지할지 결정해요.

    오늘 바로 써먹기¶

    • 검사 도구의 조용한 옵션(-q)이 실패를 숨기지 않는지 한 번 확인하기
    • 새 검사는 틀린 경우와 맞는 경우를 모두 시험하고 등록하기
    • 훅이 Claude를 되돌려 보내는 검사에는 반복 방지 장치를 꼭 넣기

    자주 하는 오해¶

    • "빌드가 통과하면 내용도 맞다?" 빌드는 형식과 링크만 봐요. 내용은 ③의 검토자와 내 눈이 맡아요.
    • "검사가 많을수록 안전하다?" 느려지고 귀찮아서 끄게 되면 소용없어요. 중요한 것 두세 겹이 낫습니다.
