# 주제 페이지 작성

이 책의 독자는 "AI를 써 보고 싶은데 잘 쓰는지 모르겠는" 사람이다. 그래서 모든 페이지는 읽고 나서 **무언가를 해 볼 수 있어야** 하고, 다음 페이지가 궁금해야 한다. 페이지는 3~5분 영상 한 편으로도 만들 것이라 한 페이지에 한 가지 생각만 담는다.

## 페이지 틀 (이 순서)

1. `# 제목`: 질문이나 한 문장 주장. 예: 챗봇은 '다음 말'을 맞히는 기계
2. `!!! abstract "이 페이지에서 배우는 것"`: 3줄 이내. 핵심 문장은 `==형광펜==`으로 표시한다. 한 페이지에 형광펜은 2~3곳만 쓴다. 많으면 효과가 사라진다.
3. 본문 `## 1.` `## 2.` ...: 일상 비유 → 구체 예시 → 원리 순서. 문장은 짧게, "~예요/~해요"체.
4. `!!! tip "10살 눈높이 한 줄 요약"`: 한 줄.
5. `!!! note "★ 한 걸음 더 (심화)"`: 전문 용어는 여기에만 둔다.
6. `## 직접 해보기`: 2분 안에 끝나는 실험 하나.
7. `## 오늘 바로 써먹기`: 이 페이지의 원리에서 나오는 요령 2~3개. 복사해 붙일 수 있는 예시 문장을 코드 블록으로 준다. 원리와 연결되지 않는 일반 조언은 쓰지 않는다.
8. `## 자주 하는 오해`
9. `## 출처와 기준`: 아래 규칙.

## 한국어 다듬기 (2026-11-08)

문장을 쓴 뒤 `natural-writing-kr` 스킬(`.claude/skills/natural-writing-kr`)의 기준으로 한 번 훑는다. 번역투와 겹말은 줄이되, 이미 자연스러운 문장과 사실·숫자·인용은 건드리지 않는다. 영상 문구는 `video-script` 스킬의 "AI 티 점검표"도 따른다.

## 출처 규칙

- 영어 원전(Karpathy, 3Blue1Brown, Anthropic 등)을 읽고 **이해한 내용을 다시 쓴다.** 문장을 옮기지 않는다.
- 링크는 쓰기 전에 실제로 열어서 제목과 날짜를 확인한다(`curl -sIL`, 영상은 oembed). 확인하지 못한 것은 "확인 필요"로 적고 확인된 것처럼 쓰지 않는다.
- 기준 날짜를 오늘 날짜로 적는다. 시간이 지나면 낡는 내용(모델 이름, 가격, 기능)에는 날짜를 더 가깝게 붙인다.
- 지어낸 숫자나 예시는 "예시"라고 본문에 밝힌다.

## V부 Claude Code 실전 페이지 (2026-11-07 추가)

- 원전은 luongnv89/claude-howto(MIT)의 모듈이고, **사실 기준은 공식 문서** https://code.claude.com/docs 다. 둘이 다르면 공식 문서를 따른다. 순서는 폴더 번호가 아니라 그 저장소 LEARNING-ROADMAP.md의 권장 순서다.
- `## 출처와 기준`에 **기준 Claude Code 버전(`claude --version`이나 npm 최신 버전)과 확인일**을 반드시 적는다. 버전 제한이 있는 기능은 "v○ 이상"을 밝힌다.
- 실습 예제는 우리 채널 제작 흐름(영상 한 편 만들기 스킬 → 조사·대본·검토 에이전트 → studio 플러그인)으로 쓴다.
- 만들어 본 것과 못 본 것을 구분해 쓴다. 스크립트·플러그인은 실제로 돌려 검증하고, 모델을 호출해야 하는 결과나 계정이 필요한 연결은 "직접 확인하지 않았다"고 밝힌다.
- 훅·남의 저장소의 `.claude/`·MCP 토큰의 안전 수칙은 해당 장에 반드시 둔다.

## 인터뷰·대담을 참고할 때

인터뷰는 사실이 아니라 발언과 견해다. 누가 언제 어디서 한 말인지 밝히고, 사실 설명과 구분해서 쓴다. 예측은 예측이라고 적고 기준 날짜를 붙인다. 인용은 최소로 하고 다시 풀어 쓴다. 입장이 갈리는 주제는 한쪽만 싣지 않는다.

## 작업 방식

- 사용자가 "그만"이라고 할 때까지 페이지를 이어서 쓴다(2026-11-07 승인). 사용자 평가가 들어오면 이어 쓰던 페이지 전에 먼저 반영한다.
- 스타일이 필요하면 `mkdocs.yml`의 nav에 먼저 추가하고 `mkdocs build`가 경고 없이 통과하는지 확인한다.
- 디자인을 건드릴 때는 `.claude/skills/frontend-design`을 따른다.
