# 파일을 넘겨 한 줄로 일 시키기

!!! abstract "이 페이지에서 배우는 것"
    - 터미널의 `|`(파이프)는 ==앞 명령의 결과를 뒤 명령에게 넘기는 관==이에요.
    - `cat 파일 | claude -p "…"` 한 줄이면 파일 내용을 읽혀서 일을 시킬 수 있어요.
    - 이 한 줄이 5.10의 자동화 파이프라인의 첫 조각이에요.

## 1. 컨베이어 벨트

공장 컨베이어 벨트를 상상해 봐요. 첫 번째 기계가 물건을 만들면 벨트가 두 번째 기계로 실어 가요. 터미널의 `|` 기호가 이 벨트예요. `cat`은 파일 내용을 꺼내는 기계이고, `claude -p`는 그 내용을 읽고 처리하는 기계예요.

```bash
cat error.log | claude -p "이 오류가 왜 났는지 세 줄로 설명해 줘"
```

결과를 파일로 저장하려면 `>`를 붙여요.

```bash
cat 대본.md | claude -p "어려운 말에 표시를 해 줘" > 점검결과.md
```

공식 문서의 예시도 이 모양이에요. 빌드 오류 파일을 넘겨서 원인을 간단히 설명하게 하고 그 결과를 파일에 저장해요.

## 2. 우리 채널 제작에 붙이기

대본 한 편을 쓰면 이런 점검을 하고 싶어요. 이 점검을 한 줄로 만들 수 있어요.

```bash
cat docs/part1/ch01/next-word.md | claude -p "10살이 읽기에 어려운 단어를 찾아 목록으로만 줘"
```

변경한 부분만 검사하는 것도 가능해요. 공식 문서는 `git diff main | claude -p "…"`처럼 바뀐 내용만 넘겨 오타를 찾는 예를 보여 줘요.

## 3. 결과 모양 정하기

사람이 읽으려면 글로 충분하지만, 다른 프로그램이 읽으려면 모양이 정해져 있어야 해요.

```bash
claude -p "이 책의 부 이름을 알려 줘" --output-format json
```

`--output-format`은 `text`(기본), `json`, `stream-json`을 고를 수 있어요. 결과가 꼭 이 틀을 지켜야 하면 `--json-schema`로 틀을 직접 줄 수도 있는데, 이건 5.10에서 써 봐요.

!!! tip "10살 눈높이 한 줄 요약"
    `|`는 컨베이어 벨트예요. 파일을 AI에게 실어 보내면 한 줄로 일이 끝나요.

!!! note "★ 한 걸음 더 (심화)"
    한 줄 모드에서는 질문이 오지 않으니, 파일을 고치거나 명령을 실행하는 일은 미리 허락해 두어야 해요. `--allowedTools "Read,Edit"`처럼 도구를 허락하는 옵션이 있어요. 허락은 필요한 만큼만, 좁게 줘요. 허락 목록이 넓을수록 실수가 났을 때 피해가 커져요.

## 직접 해보기

1. 아무 텍스트 파일을 하나 골라요(이 책의 `docs` 폴더 안 마크다운도 좋아요).
2. `cat 파일 | claude -p "이 글을 세 줄로 요약해 줘"`를 실행해 봐요.
3. 마지막에 `> 요약.txt`를 붙여서 결과가 파일로 저장되는지 확인해요.

## 오늘 바로 써먹기

- 긴 오류 메시지는 복사하지 말고 파이프로 넘기기
- 같은 점검을 두 번 하게 되면 한 줄 명령을 메모장에 적어 두기. 곧 스킬(5.5)이나 스크립트(5.10)가 돼요.
- 파일을 넘기기 전에 비밀번호나 개인정보가 들어 있지 않은지 확인하기. 넘긴 내용은 AI 서비스로 보내져요.

## 자주 하는 오해

- "파이프는 개발자만 쓴다?" 아니에요. 파일 내용을 넘기는 것뿐이라 처음 한 번만 익히면 돼요.
- "한 줄 모드는 아무 파일이나 고친다?" `--allowedTools`는 "묻지 않고 써도 되는 도구"를 정하는 옵션이고, 쓸 수 있는 도구 자체를 줄이는 것은 `--tools`예요. 한 줄 모드에서는 허락 여부를 물어볼 사람이 없으니, 허락이 없는 도구 호출은 거절될 수 있어요. 허락을 넓게 주지 않는 게 안전해요.
