# 체크포인트와 git은 뭐가 다를까

!!! abstract "이 페이지에서 배우는 것"
    - 체크포인트는 ==지금 대화 안에서 쓰는 빠른 되돌리기==이고, 오래 남는 기록은 git이 맡아요.
    - 체크포인트가 **못 되돌리는 것** 네 가지를 알아 둬요.
    - 그래서 "저장 지점 + 커밋" 두 겹으로 일하는 습관이 안전해요.

## 1. 연필 지우개와 사진첩

체크포인트는 연필로 쓴 글의 지우개 같아요. 방금 쓴 걸 빨리 지울 수 있지만, 연습장을 오래 두면 흐려져요. git은 사진첩이에요. 중요한 순간을 사진으로 찍어 두고, 몇 달 뒤에도 찾아보고, 다른 사람과 나눌 수 있죠. 공식 문서도 체크포인트는 "대화 안에서의 빠른 복구용"이고, 오래 남는 기록과 협업은 git 같은 버전 관리가 맡는다고 말해요.

## 2. 체크포인트가 못 하는 것

| 못 하는 것 | 이유와 대처 |
|---|---|
| 명령창(Bash) 명령으로만 바뀐 파일 | Claude가 파일 편집 도구로 만진 적 없는 파일은 추적 안 돼요. git으로 되돌려요 |
| 서브에이전트가 바꾼 파일 | 대부분 되돌려지지 않아요. git으로 되돌려요 |
| 내가 직접 고친 파일, 다른 창에서 한 일 | Claude Code 밖의 변경은 보통 추적 안 돼요 |
| 바로가기(심볼릭 링크)와 하드 링크 파일 | 건너뛰고 경고가 떠요 |

한 가지 더, 일하는 도중 내가 끼어들어 보낸 말은 자기 저장 지점이 없어서 "코드 복원 없음"으로 표시될 수 있어요. 이때는 그 턴을 시작한 말을 골라 되돌려요.

## 3. 두 겹 습관

1. 새 작업을 시작하기 전에 지금 상태를 커밋해 둬요. 커밋은 사진첩에 넣는 거예요.
2. 작업 중에는 마음껏 시키고, 틀어지면 `/rewind`로 빠르게 되돌려요.
3. 마음에 드는 결과가 나오면 다시 커밋해요.

이 책 저장소도 페이지를 하나 쓸 때마다 커밋해요. 영상 제작처럼 파일이 많은 작업에서 체크포인트만 믿으면, 명령창으로 만든 영상 파일은 못 지킬 수 있어요.

!!! tip "10살 눈높이 한 줄 요약"
    체크포인트는 지우개, git은 사진첩이에요. 중요한 건 사진첩에 넣어요.

!!! note "★ 한 걸음 더 (심화)"
    같은 대화에서 가지를 쳐서 다른 방법을 시험하는 `/branch`, 그리고 서로 간섭하지 않도록 작업 폴더를 따로 만드는 "워크트리"도 있어요. 둘 다 5C에서 다시 만나요.

## 직접 해보기

연습용 폴더에서 `git init`을 한 뒤, Claude에게 파일을 만들게 하고 커밋해요. 이어서 "파일 이름을 전부 바꿔 줘"라고 시킨 다음, 이번에는 `/rewind`가 아니라 `git restore`나 `git checkout`으로 되돌려 봐요. 두 방법의 느낌이 어떻게 다른지 비교해요.

## 오늘 바로 써먹기

- 큰 작업 전에는 먼저 이렇게 시키기

```text
지금까지 바뀐 파일을 확인하고, 커밋 메시지 초안을 한 줄로 써 줘. 커밋은 내가 확인한 뒤에 해.
```

- 서브에이전트(5.8)를 쓰기 전에는 반드시 커밋부터

## 자주 하는 오해

- "체크포인트가 있으니 git은 필요 없다?" 아니에요. 오래된 기록은 정리되고, 일부 변경은 추적되지 않아요.
- "git을 모르면 Claude Code를 못 쓴다?" 쓸 수 있어요. 다만 중요한 작업이 늘면 git을 배울 가치가 커져요.
