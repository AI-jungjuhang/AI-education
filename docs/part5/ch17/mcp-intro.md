# MCP는 Claude의 연결 잭

!!! abstract "이 페이지에서 배우는 것"
    - MCP는 Claude Code를 ==바깥 서비스(노션, 깃허브, 데이터베이스)에 꽂는 표준 규격==이에요.
    - 4장에서 배운 "도구 쓰는 AI"를 내 서비스까지 넓히는 방법이에요.
    - 연결할수록 편해지지만, **연결할수록 위험도 커져요.**

## 1. 멀티탭의 구멍

기기마다 플러그 모양이 다르면 불편하겠죠. 그래서 콘센트 규격이 통일돼 있어요. MCP(Model Context Protocol)가 바로 AI 도구의 "콘센트 규격"이에요. 서비스 쪽에서 이 규격에 맞는 서버를 열어 두면 Claude Code는 그걸 꽂아서 쓸 수 있어요. 공식 문서는 MCP를 AI와 도구를 잇는 열린 표준이라고 설명해요.

언제 필요할까요? 공식 문서의 기준이 쉬워요. **다른 서비스의 내용을 대화창에 자꾸 복사해 붙이고 있다면** 연결할 때예요. 이슈 목록, 모니터링 화면, 노션 문서를 일일이 붙여 넣는 대신, Claude가 직접 읽고 일하게 할 수 있어요.

## 2. 스킬, 훅, MCP 한 번에 비교

| | 하는 일 | 비유 |
|---|---|---|
| 스킬(5.5) | 일하는 **방법**을 알려 줘요 | 레시피 카드 |
| 훅(5.6) | 정해진 순간에 **자동으로** 실행돼요 | 센서등 |
| MCP(5.7) | **바깥 서비스**에 연결해요 | 콘센트 |
| 서브에이전트(5.8) | 일을 **나눠 맡겨요** | 조수 |

## 3. 어떤 종류가 있나

연결 방식(전송 방식)은 네 가지가 있어요. 처음에는 **원격 HTTP 서버**만 알면 돼요. 공식 문서도 클라우드 서비스에는 HTTP 방식을 권해요. 내 컴퓨터에서 직접 실행하는 서버(stdio)도 있지만, 그 서버는 내 권한으로 프로그램이 도는 것이라 5.7의 안전 수칙에서 따로 다뤄요.

연결 정보를 어디에 저장하느냐(범위)도 달라요.

| 범위 | 어디서 쓰나 | 팀과 공유 |
|---|---|---|
| 로컬 | 이 프로젝트만 | 아니요 |
| 프로젝트 | 이 프로젝트만 | 예 (저장소의 `.mcp.json`) |
| 사용자 | 내 모든 프로젝트 | 아니요 |

!!! tip "10살 눈높이 한 줄 요약"
    MCP는 AI의 콘센트 규격이에요. 규격이 같아서 어떤 서비스든 꽂을 수 있어요.

!!! note "★ 한 걸음 더 (심화)"
    MCP 서버는 "도구"뿐 아니라 "자료(리소스)"와 "프롬프트"도 줄 수 있어요. 도구가 많이 연결되면 도구 설명이 기억 공간을 차지하는데, Claude Code에는 필요한 도구만 찾아 쓰는 도구 검색 기능이 있어서 그 비용을 줄여 줘요. 또 Claude Code 자신이 MCP 서버가 되어 다른 앱에서 불릴 수도 있어요.

## 직접 해보기

Claude Code에서 `/mcp`를 입력해 보세요. 연결된 서버 목록과 상태가 나와요. 아직 아무것도 연결하지 않았다면 비어 있을 거예요. 터미널에서는 이렇게도 볼 수 있어요.

```bash
claude mcp list
```

## 오늘 바로 써먹기

- 같은 외부 내용을 복사해서 붙인 횟수가 세 번을 넘으면 연결 후보로 적어 두기
- 연결하기 전에 "이 서비스에서 Claude가 **읽기만** 하면 되나, **쓰기도** 해야 하나?"부터 정하기
- 연결 목록은 가끔 `/mcp`로 점검하고 안 쓰는 건 끊기

## 자주 하는 오해

- "MCP를 연결하면 Claude가 그 서비스를 완벽히 안다?" 연결은 문을 연 것일 뿐이에요. 어떻게 쓸지는 여전히 내가 시켜야 해요.
- "공식 목록에 있으면 안전하다?" 공식 문서도 서버를 연결하기 전에 믿을 수 있는지 스스로 확인하라고 해요. Anthropic이 연결 목록(디렉터리)에 올리기 전에 기준으로 검토하지만, 개별 MCP 서버를 보안 감사하거나 관리하지는 않는다고 밝혀요.
