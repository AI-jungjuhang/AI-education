# SKILL.md는 어떻게 생겼을까

!!! abstract "이 페이지에서 배우는 것"
    - 스킬은 폴더 하나이고, 그 안의 `SKILL.md`가 설명서예요. 위쪽은 **이름표**, 아래쪽은 **절차**예요.
    - 평소에는 ==이름표(설명)만 기억 공간에 올라가고, 본문은 쓸 때만 올라와요.== 그래서 길어도 부담이 적어요.
    - "누가 부를 수 있나"를 정하는 두 스위치를 알아요.

## 1. 요리책 한 권이 아니라 레시피 카드 한 장

주방에 레시피 책이 100권 있다고 해 봐요. 요리사가 시작할 때마다 100권을 다 읽는다면 아무 요리도 못 하겠죠. 스킬은 반대로 움직여요. 처음에는 **카드의 제목과 한 줄 설명**만 벽에 붙여 두고, 필요한 카드만 꺼내서 끝까지 읽어요. 공식 문서도 스킬 본문은 쓸 때만 올라와서, 긴 참고 자료도 쓰기 전까지는 거의 비용이 들지 않는다고 설명해요.

반대로 5.2의 CLAUDE.md는 시작할 때마다 통째로 읽혀요. 그래서 "항상 필요한 사실"은 메모에, "가끔 필요한 절차"는 스킬에 넣어요.

## 2. 파일 모양

```text
make-short/
├── SKILL.md        ← 필수. 이름표 + 절차
├── template.html   ← 참고 파일(필요할 때만 읽혀요)
└── scripts/
    └── render.sh   ← 실행하는 도구 (읽히는 게 아니라 실행돼요)
```

`SKILL.md`의 앞부분은 `---` 두 줄 사이에 쓰는 이름표(프런트매터)예요. 자주 쓰는 칸은 이 정도예요.

| 칸 | 뜻 |
|---|---|
| `name` | 명령 이름. 안 쓰면 폴더 이름이 이름이 돼요 |
| `description` | 무엇을 하고 언제 쓰는지. **Claude가 이 글을 보고 쓸지 정해요** |
| `disable-model-invocation` | `true`면 Claude가 마음대로 부르지 못하고 내가 `/이름`으로만 불러요 |
| `user-invocable` | `false`면 나는 못 부르고 Claude만 불러요(배경 지식용) |
| `allowed-tools` | 이 스킬이 실행되는 동안 묻지 않고 써도 되는 도구 |
| `argument-hint` | 입력창에 보이는 인자 힌트 |

칸 이름은 표와 글자 하나까지 같아야 해요. 모르는 칸 이름은 오류 없이 무시되기 때문에, 오타가 나면 조용히 안 먹혀요.

## 3. 누가 부르게 할까: 두 스위치

- **보내기·배포처럼 부작용이 있는 일**은 `disable-model-invocation: true`로 해서 내가 직접 부를 때만 실행해요. 공식 문서도 "코드가 준비돼 보인다고 Claude가 알아서 배포하면 곤란하다"는 식으로 설명해요.
- **옛 시스템 설명 같은 배경 지식**은 `user-invocable: false`로 해서 Claude만 필요할 때 읽게 해요.

!!! tip "10살 눈높이 한 줄 요약"
    스킬은 레시피 카드예요. 제목만 벽에 붙여 두고, 필요한 카드만 꺼내 읽어요.

!!! note "★ 한 걸음 더 (심화)"
    스킬의 `description`은 이름표 목록에서 길이 제한(약 1,500자)이 있고, 앞부분에 핵심 용도를 써야 안 잘려요. `context: fork`를 쓰면 스킬이 따로 떼어낸 작업 공간(서브에이전트)에서 돌아서 내 대화를 어지럽히지 않아요. `paths`로 특정 파일을 다룰 때만 자동으로 켜지게 할 수도 있어요. 서브에이전트는 5.8에서 다뤄요.

## 직접 해보기

1. 5.1에서 만든 `~/.claude/skills/easy/SKILL.md`를 열어요.
2. 이름표에 `argument-hint: [고칠 글]`을 한 줄 추가해요.
3. Claude Code에서 `/easy`를 쳤을 때 입력창에 힌트가 보이는지 확인해요. 안 보이면 칸 이름을 표와 한 글자씩 비교해 봐요.
4. `/skills`를 쳐서 내 스킬 목록에 `easy`가 보이는지 확인해요.

## 오늘 바로 써먹기

- `description`에는 "무엇을 한다 + 언제 쓴다"를 한 문장씩 쓰기. 언제 쓰는지가 있어야 Claude가 알아서 불러요.
- 본문이 길어지면 참고 자료는 따로 파일로 빼고 SKILL.md에서 "언제 읽을지"를 한 줄로 안내하기
- 부작용이 있는 스킬에는 `disable-model-invocation: true`를 먼저 붙이기

## 자주 하는 오해

- "스킬이 많으면 항상 느려진다?" 본문은 쓸 때만 올라와서 목록 설명만 짧게 쓰면 부담이 적어요. 다만 설명이 너무 많으면 그것도 기억 공간을 써요.
- "`description`은 대충 써도 된다?" 가장 중요한 칸이에요. Claude가 이 글로 자동 사용 여부를 정해요.
