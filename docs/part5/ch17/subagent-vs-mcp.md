# 서브에이전트와 MCP는 뭐가 다를까

!!! abstract "이 페이지에서 배우는 것"
    - 5B의 네 도구(스킬·훅·MCP·서브에이전트)를 =="무엇이 필요한가?"로 골라 쓰는 표==로 정리해요.
    - 서브에이전트와 MCP는 자주 헷갈려요. 한 줄로 가르면 "**누가 일하나**"와 "**어디에 닿나**"예요.
    - 메인 대화로 하는 게 나은 때도 있어요.

## 1. 한 줄 구분

- **MCP**: Claude Code가 닿을 수 있는 **곳**을 넓혀요. 노션, 깃허브, 데이터베이스 같은 바깥 서비스예요.
- **서브에이전트**: Claude Code의 **일하는 사람**을 늘려요. 같은 AI가 다른 작업 공간에서 일해요.

둘은 함께 쓸 수도 있어요. 서브에이전트의 `mcpServers` 칸으로 "이 조수만 노션에 닿게" 할 수도 있고, 쓸 도구도 제한할 수 있어요.

## 2. 골라 쓰는 표

| 이런 상황이면 | 이걸 써요 |
|---|---|
| 같은 절차를 계속 반복해서 시킨다 | 스킬(5.5) |
| 꼭 해야 하는 일이 있고 AI 판단에 맡기기 싫다 | 훅(5.6) |
| 다른 서비스의 내용을 계속 복사해 붙인다 | MCP(5.7) |
| 긴 출력이 내 대화를 어지럽힌다 | 서브에이전트(5.8) |
| 조사자와 검토자를 나누고 싶다 | 서브에이전트(5.8) |
| 이것저것 오가며 다듬는 중이다 | 메인 대화 |

공식 문서가 메인 대화를 권하는 경우도 있어요. 자주 주고받으며 다듬는 일, 여러 단계가 맥락을 공유하는 일, 빠른 수정, 속도가 중요한 일이에요. 서브에이전트는 처음부터 시작해서 맥락을 모으는 데 시간이 걸리기 때문이에요.

## 3. 우리 채널에 적용하면

| 단계 | 도구 | 이유 |
|---|---|---|
| 노션에 적어 둔 아이디어 읽기 | MCP | 바깥 서비스 |
| 페이지 → 핵심 정리 | researcher | 긴 읽기를 내 대화 밖에서 |
| 대본 쓰기 | scriptwriter | 정리만 받아서 쓰기 |
| 대본 검사 | reviewer | 처음 보는 눈 |
| 모든 단계의 순서와 기준 | 스킬 | 절차를 글로 저장 |
| 저장 후 형식 검사 | 훅 | 빠뜨리면 안 되는 약속 |

이 표가 곧 5.10에서 만들 슈퍼 스킬의 설계도예요.

!!! tip "10살 눈높이 한 줄 요약"
    MCP는 갈 수 있는 곳을 늘리고, 서브에이전트는 일하는 사람을 늘려요.

!!! note "★ 한 걸음 더 (심화)"
    같은 대화에서 가지를 쳐서 다른 방법을 시도하는 '포크'와 서브에이전트는 비슷하지만 달라요. 서브에이전트는 처음부터 시작하고, 포크는 지금 대화의 맥락을 물려받아요. 여러 조수를 동시에 돌리는 에이전트 팀은 5C에서 다뤄요.

## 직접 해보기

최근 일주일 동안 AI에게 시킨 일 세 가지를 떠올려서 위의 표에서 어느 도구가 어울렸을지 적어 봐요. 하나는 "메인 대화로 충분했다"가 나올 수 있어요. 그게 정답일 때도 많아요.

## 오늘 바로 써먹기

- 도구를 고르기 전에 "필요한 게 방법, 약속, 연결, 분업 중 무엇인가?"를 먼저 묻기
- 처음에는 메인 대화로 해 보고, 반복되거나 어질러질 때 도구로 옮기기

## 자주 하는 오해

- "도구를 많이 쓸수록 고수다?" 아니에요. 필요한 만큼만 쓰는 사람이 고수예요.
- "서브에이전트를 쓰면 더 똑똑한 AI가 된다?" 같은 AI를 다른 책상에서 일하게 하는 것이지 더 똑똑해지는 것은 아니에요.
