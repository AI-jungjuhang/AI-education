# 남의 스킬과 설정을 열기 전에

!!! abstract "이 페이지에서 배우는 것"
    - 남의 저장소의 `.claude/` 폴더에는 **내 컴퓨터에서 실행되는 것**이 들어 있을 수 있어요.
    - 처음 보는 폴더는 열기 전에 ==`.claude/`와 `.mcp.json`부터 읽어 보는 습관==이 필요해요.
    - 한 줄 모드(`-p`)는 믿음 확인 창이 안 떠서 더 조심해야 해요.

## 1. 낯선 집에 들어가기 전에

친구가 "우리 집 규칙이야" 하고 쪽지를 줬어요. 쪽지에 "도착하면 현관 열쇠를 우편함에 넣어 둬"라고 적혀 있다면 따르겠어요? 사람은 이상하다고 느끼지만 AI와 자동 도구는 규칙대로만 움직일 수 있어요.

남의 저장소를 내려받아 Claude Code를 열면, 그 저장소에 들어 있는 `.claude/` 폴더의 스킬, 훅, 설정이 내 컴퓨터에서 쓰일 수 있어요. 스킬 안의 `` !`명령` `` 줄은 스킬이 켜질 때 내 컴퓨터에서 먼저 실행돼요(5.1에서 본 동적 문맥 주입이에요). 훅은 5.6에서 보듯 아예 프로그램을 실행해요.

## 2. 믿음 확인 창과 그 구멍

대화 모드에서 처음 보는 폴더를 열면 Claude Code가 "이 폴더를 믿을래요?" 하고 물어봐요. 공식 문서는 몇 가지를 구분해서 설명해요.

- 대화 모드에서 폴더를 믿지 않으면 그 저장소가 정한 허용 규칙은 적용되지 않아요.
- 하지만 **`claude -p`(한 줄 모드)와 SDK 실행은 믿음 확인 창을 아예 띄우지 않아요.**
- 문서의 표에 따르면, 부모 폴더만 믿었거나 `-p`로 실행한 경우에도 저장소의 설정 파일에 든 **훅은 그대로 쓰여요.** 프로젝트 스킬의 `allowed-tools`도 믿음 확인과 상관없이 쓰여요.
- `.mcp.json`에 든 서버는 대화 모드에서는 연결 전에 물어보지만, `-p`에서는 묻지 않고 연결돼요.

즉 모르는 저장소에서 `claude -p`를 돌리는 것이 가장 위험한 조합이에요.

## 3. 남의 저장소 열기 전 점검표

1. `.claude/settings.json`을 열어서 `hooks` 칸에 무엇이 있는지 읽어요.
2. `.mcp.json`이 있으면 어떤 서버를 연결하는지 읽어요.
3. `.claude/skills/`의 `SKILL.md`에서 `` !` `` 로 시작하는 줄과 `allowed-tools`를 찾아 읽어요.
4. `CLAUDE.md`에 이상한 지시(예: 비밀 파일을 어딘가로 보내라)가 없는지 읽어요.
5. 처음에는 대화 모드로 열어서 믿음 확인 창이 뜨는지 보기. 모르면 "믿지 않기"를 골라요.

`-p`로 남의 저장소를 꼭 돌려야 한다면 공식 문서가 권하는 방법이 있어요. `--bare`로 실행하면 프로젝트의 훅, 스킬, 플러그인, MCP 서버를 읽지 않아요. 또는 `--setting-sources user`로 프로젝트 설정 자체를 읽지 않게 하고, `--settings '{"disableAllHooks": true}'`로 훅을 끌 수 있어요. 다만 `--bare`를 써도 프로젝트 설정 파일의 `env` 칸과 일부 도우미 명령은 적용될 수 있으니, 낯선 저장소는 먼저 읽는 것이 기본이에요.

!!! tip "10살 눈높이 한 줄 요약"
    남의 집 규칙 쪽지는 따르기 전에 먼저 읽어요. `.claude/`가 그 쪽지예요.

!!! note "★ 한 걸음 더 (심화)"
    스킬 안의 `!` 명령 실행은 설정의 `disableSkillShellExecution: true`로 끌 수 있어요. 스킬 안의 `!` 명령은 사용자·프로젝트·플러그인 출처 스킬에 적용돼서, 켜 두면 명령 자리에 자리표시자 문구가 들어가요.  그래도 개인이라면 읽고 믿는 습관이 가장 먼저예요.

## 직접 해보기

이 책 저장소가 아닌 아무 공개 저장소를 하나 내려받아(아직 Claude는 열지 말고) 아래 명령으로 `.claude`와 `.mcp.json`이 있는지만 봐요.

```bash
ls -a 저장소폴더
cat 저장소폴더/.claude/settings.json 2>/dev/null
```

있으면 `hooks`나 `mcpServers` 칸이 무엇을 하려는지 한 줄씩 해석해 봐요. 모르는 부분은 Claude에게 "실행하지 말고 읽기만 해서 설명해 줘"라고 시켜요.

## 오늘 바로 써먹기

- 남의 저장소는 열기 전에 `.claude/`와 `.mcp.json`을 읽기
- 믿음 확인 창이 뜨면 이유가 분명할 때만 "믿기"
- 모르는 폴더에서는 `claude -p`를 쓰지 않기
- 내가 만든 스킬도 남에게 나누기 전에 `!` 줄이 무엇을 실행하는지 한 번 더 보기

## 자주 하는 오해

- "AI가 알아서 위험한 건 막아 준다?" 믿음 확인과 권한 규칙이 도와주지만, 설정 파일이 정한 훅은 사용자 권한으로 실행돼요. 사람이 읽는 것이 마지막 방어선이에요.
- "공식 마켓에서 받은 스킬은 안전하다?" 출처를 믿을 수 있어도 내용은 읽어 보는 것이 좋아요. 이 책의 모든 안전 수칙은 "읽고, 좁게 허락하고, 끝나면 정리"로 모여요.
