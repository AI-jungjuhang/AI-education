# 플러그인으로 묶어 나누기

!!! abstract "이 페이지에서 배우는 것"
    - 플러그인은 스킬·에이전트·훅·MCP를 ==폴더 하나로 묶어서 설치·공유하는 상자==예요.
    - 폴더 모양과 `plugin.json` 한 장이면 만들 수 있어요.
    - **설치한 플러그인은 내 권한으로 실행돼요.** 만드는 법과 믿는 법을 같이 배워요.

## 1. 이사 상자

이사할 때 물건을 하나씩 옮기지 않고 상자에 담죠. 5B에서 만든 스킬, 조수, 훅이 여기저기 흩어져 있다면 새 컴퓨터나 동료에게 옮기기 번거로워요. 플러그인은 그 모든 걸 담는 이사 상자예요. 공식 문서도 플러그인을 "스킬, 에이전트, 훅, MCP 서버 등을 하나의 단위로 설치하고 불러오는 폴더"라고 설명해요.

## 2. 폴더 모양

```text
studio/
├── .claude-plugin/
│   └── plugin.json        ← 이름표 (여기에는 이것만!)
├── skills/
│   ├── make-short/SKILL.md
│   └── episode/SKILL.md
├── agents/
│   ├── researcher.md
│   ├── scriptwriter.md
│   └── reviewer.md
├── hooks/
│   └── hooks.json
└── scripts/
    └── check-page.sh
```

`plugin.json`은 이렇게 짧아요.

```json
{
  "name": "studio",
  "description": "책 페이지 하나를 쇼츠 영상 대본으로 만드는 제작 도구 모음",
  "version": "0.1.0",
  "author": { "name": "채널 제작팀" }
}
```

- `name`은 꼭 필요해요. 공백은 쓰지 않아요. 스킬 이름 앞에 붙는 말(이름표)이 되어서 `/studio:episode`처럼 불러요.
- `.claude-plugin/` 안에는 `plugin.json`만 넣어요. 거기에 넣은 다른 파일은 불러와지지 않아요.
- 훅 안에서 플러그인 안의 스크립트는 `${CLAUDE_PLUGIN_ROOT}/scripts/…`처럼 경로를 써서 불러요.

## 3. 시험해 보기

플러그인은 설치하지 않고도 한 번만 불러서 시험할 수 있어요.

```bash
claude --plugin-dir ./studio
```

만든 폴더가 규칙에 맞는지 검사하는 명령도 있어요.

```bash
claude plugin validate ./studio
```

이 책의 `studio` 예시 플러그인으로 이 검사를 실제로 돌렸고 통과했어요. README, 라이선스, 아이콘이 없다는 안내는 나왔는데, 이것은 공식 디렉터리에 올릴 때 필요한 것이라 내 컴퓨터에서 쓰는 데는 상관없어요.

## 4. 설치와 믿음

남이 만든 플러그인은 `/plugin`에서 찾아 설치해요. 공식 문서의 경고는 분명해요. **설치한 플러그인은 내 사용자 권한으로 임의의 코드를 실행할 수 있어요.** 플러그인에 든 훅과 MCP 서버, 백그라운드 모니터는 Claude Code의 권한 규칙이나 샌드박스 밖에서 돌 수 있다고 해요. 그래서 설치 전에 이렇게 해요.

1. 플러그인 폴더의 `hooks/`, `.mcp.json`, `scripts/`, `bin/`을 읽어요.
2. 어떤 마켓에서 왔는지 확인해요. 마켓 이름은 카탈로그를 낸 사람을 알려 줄 뿐, 그 안의 각 플러그인이 안전하다는 뜻은 아니에요.
3. 자동 업데이트가 켜져 있으면 내가 읽은 내용이 나중에 바뀔 수 있다는 점을 알아 둬요.
4. 쓰지 않으면 끄거나 지워요(`claude plugin disable`).

!!! tip "10살 눈높이 한 줄 요약"
    플러그인은 이사 상자예요. 내 상자는 라벨을 붙여 나누고, 남의 상자는 열어 보고 받아요.

!!! note "★ 한 걸음 더 (심화)"
    활성화된 플러그인은 **그 플러그인이 켜진 모든 대화**에 영향을 줘요. 스킬과 에이전트의 이름과 설명이 매 턴마다 Claude의 기억 공간에 올라가서 사용량과 남은 공간을 쓰기 때문이에요. 공식 플러그인 마켓에서는 `/plugin`에서 설치 전에 "컨텍스트 비용" 추정치를 볼 수 있다고 문서에 나와요. 오래 안 쓴 플러그인은 설치된 목록의 "최근 안 씀" 그룹에서 확인할 수 있어요.

## 직접 해보기

1. 5B에서 만든 스킬, 에이전트, 훅 파일을 위 폴더 모양으로 모아요.
2. `plugin.json`을 쓰고 `claude plugin validate`를 돌려 통과하는지 확인해요.
3. `claude --plugin-dir ./studio`로 열고, `/skills`나 `/` 목록에서 `studio:`로 시작하는 이름이 보이는지 확인해요.

## 오늘 바로 써먹기

- 스킬·훅·에이전트가 서너 개를 넘으면 플러그인으로 묶기
- 나눌 때는 README에 "무엇을 실행하는지"(훅, 스크립트)를 적기
- 설치 전 점검표: 훅, MCP, scripts, bin을 읽었나? 출처를 확인했나?

## 자주 하는 오해

- "플러그인은 공식 마켓에 있으면 믿어도 된다?" 이름이 공식 마켓이어도 개별 플러그인은 읽어 보는 것이 좋아요.
- "플러그인을 만들려면 코드를 짜야 한다?" 스킬과 에이전트는 글(마크다운)이고, 필요하면 훅 스크립트만 코드예요.
