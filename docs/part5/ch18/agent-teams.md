# 에이전트 팀

!!! abstract "이 페이지에서 배우는 것"
    - 에이전트 팀은 여러 Claude Code 세션이 ==공유 할 일 목록으로 협업하고 서로 직접 대화==하는 방식이에요.
    - 서브에이전트가 "심부름꾼"이라면 에이전트 팀은 "함께 일하는 동료"예요.
    - **실험 기능이고 기본으로 꺼져 있어요.** 쓰기 전에 가벼운 대안이 있는지 먼저 봐요.

## 1. 심부름꾼과 동료

서브에이전트는 심부름을 다녀와서 결과를 나에게만 보고해요. 에이전트 팀의 팀원들은 서로 이야기하고, 같은 할 일 목록에서 일을 가져가고, 서로의 주장을 반박하기도 해요. 한 세션이 팀장 역할로 일을 나누고 결과를 모아요. 팀원은 각자 자기 기억 공간에서 일해요. 내가 팀원에게 직접 말을 걸 수도 있어요.

| | 서브에이전트 | 에이전트 팀 |
|---|---|---|
| 기억 공간 | 각자 따로, 결과는 부른 쪽으로 돌아와요 | 각자 완전히 독립 |
| 소통 | 부른 쪽에 보고 | 팀원끼리 직접 메시지 |
| 일 나누기 | 메인이 모두 관리 | 공유 할 일 목록으로 스스로 조율 |

## 2. 언제 쓰면 좋을까

공식 문서는 병렬로 탐색하는 가치가 큰 일에 쓰라고 해요. 서로 다른 면을 동시에 조사하거나, 서로 다른 가설을 시험하거나, 서로 건드리지 않는 모듈을 각자 맡을 때예요. 반대로 순서대로 해야 하는 일, 같은 파일을 같이 고치는 일, 서로 의존이 많은 일은 한 세션이나 서브에이전트가 더 효과적이라고 해요.

우리 채널에서 어울릴 만한 예시를 하나 들면, 장면 세 개의 화면을 동시에 만들 때가 있어요. 장면 파일이 서로 겹치지 않기 때문이에요. 다만 공식 문서의 예시는 아니고, 내가 문서의 기준(서로 독립적인 일)에 맞춰 생각한 예시예요.

## 3. 켜기 전에

- 기본으로 꺼져 있어요. 환경 변수 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`을 설정 파일이나 환경에 넣어야 켜져요. 켜지 않으면 팀은 만들어지지도, 제안되지도 않아요.
- 팀은 조율하는 비용이 들고 **토큰을 훨씬 많이 써요.** 혼자 하는 것보다 비싸요.
- 알려진 제한이 있다고 공식 문서에 적혀 있어요. 쓰기 전에 문서의 제한 목록을 읽어요.

!!! tip "10살 눈높이 한 줄 요약"
    서브에이전트는 심부름꾼, 에이전트 팀은 서로 이야기하는 동료예요. 동료는 월급이 비싸요.

!!! note "★ 한 걸음 더 (심화)"
    팀보다 가벼운 길도 있어요. 내가 직접 여러 세션을 띄워 놓고 Claude가 그 사이에 결과를 전달하게 하는 '세션 간 메시지', 팀 없이 여러 작업을 한 화면에서 보는 에이전트 보기(5C 앞 페이지)가 그 예예요. 서로 통신이 필요 없다면 대부분 이쪽이 싸고 안정적이에요.

## 직접 해보기

팀을 켜지 않고도 공부할 수 있어요. 내가 하고 싶은 일 하나를 정해서 아래 질문에 답해 봐요.

1. 이 일을 서로 건드리지 않는 조각으로 나눌 수 있나?
2. 조각끼리 대화가 꼭 필요한가?
3. 서브에이전트(5.8)나 백그라운드 세션(앞 페이지)으로 충분하지 않은가?

세 질문에서 "충분하지 않다"가 나올 때만 팀을 고려해요.

## 오늘 바로 써먹기

- 팀을 쓰기 전에 서브에이전트로 먼저 해 보기
- 팀을 쓴다면 작은 일 하나로 시험하고 사용량을 확인하기
- 같은 파일을 두 팀원이 만지지 않게 일을 나누기

## 자주 하는 오해

- "팀이 크면 더 빠르고 정확하다?" 조율 비용이 늘고 오히려 어긋날 수 있어요.
- "실험 기능이어도 안정적일 것이다?" 실험 기능이라는 말은 바뀌거나 문제가 있을 수 있다는 뜻이에요.
