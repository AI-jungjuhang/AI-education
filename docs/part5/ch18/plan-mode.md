# 계획부터 세우고 맡기기

!!! abstract "이 페이지에서 배우는 것"
    - 계획 모드(plan mode)는 ==Claude가 파일을 건드리지 않고 조사와 계획만 하는 모드==예요.
    - 계획을 읽고 승인하거나 고치게 한 다음에야 실제 작업이 시작돼요.
    - 일이 크거나 헷갈릴 때, "만들기 전에 설계도를 보는" 습관이 돼요.

## 1. 집 짓기 전에 설계도

집을 짓는 사람에게 "일단 벽부터 세우세요"라고 하지 않죠. 설계도를 보고 "여기는 창문 말고 문으로 해 주세요"라고 고친 뒤에 지어요. 계획 모드가 이 설계도 단계예요. 공식 문서도 계획 모드를 "Claude가 연구하고 변경안을 제안하되 실제로는 바꾸지 않는 모드"라고 설명해요. 파일을 읽고, 탐색용 명령은 실행하지만 내 소스를 고치지는 않아요.

## 2. 켜는 법과 나오는 법

- `Shift+Tab`을 눌러 상태 표시줄이 `plan mode on`이 될 때까지 돌려요. (자동 모드 등 다른 모드와 함께 순환해요.)
- 한 번만 계획부터 하고 싶으면 질문 앞에 `/plan`을 붙여요.
- 처음부터 계획 모드로 시작하려면 이렇게 해요.

```bash
claude --permission-mode plan
```

계획이 준비되면 Claude가 계획을 보여 주고 어떻게 할지 물어요.

| 선택 | 뜻 |
|---|---|
| 승인하고 자동 모드로 진행 | 이후 작업을 알아서 하게 해요(자동 모드가 켜진 환경에서만) |
| 승인하고 수정은 하나씩 확인 | 승인하되 고칠 때마다 내가 확인해요 |
| 아니요, 계속 계획 | 계획을 더 고치게 해요 |

`Ctrl+G`로 계획을 내 편집기에서 직접 고칠 수도 있어요. 승인하는 순간 계획 모드는 끝나고 작업이 시작돼요. 계획 모드를 승인 없이 나오려면 `Shift+Tab`을 한 번 더 눌러요.

## 3. 우리 채널에서 쓴다면

"1.1.2 토큰 영상을 만들어 줘" 같은 일은 한 번에 시키면 방향이 어긋나기 쉬워요. 계획 모드로 이렇게 시켜요.

```text
/plan docs/part1/ch01/tokens.md를 쇼츠 영상으로 만들 계획을 세워 줘. 장면 수, 근거로 쓸 부분, 만들 파일 목록을 알려 줘. 파일은 아직 만들지 마.
```

계획에서 "이 장면은 원본에 없다"는 걸 발견하면 승인하지 않고 "그 장면은 빼고 다시 계획해 줘"라고 말해요. 잘못된 방향의 작업을 되돌리는 것보다 잘못된 계획을 고치는 것이 훨씬 싸요.

!!! tip "10살 눈높이 한 줄 요약"
    계획 모드는 설계도 단계예요. 설계도를 보고 고친 다음에 짓기 시작해요.

!!! note "★ 한 걸음 더 (심화)"
    계획 모드 중에 쉘 명령을 어떻게 처리하는지는 환경에 따라 달라요. 자동 모드가 켜져 있으면 분류기가 읽기용 명령인지 검토해서 승인하고, 아니면 읽기 전용 목록 밖의 명령은 내게 물어봐요. 또 `bypassPermissions`가 가능한 대화형 터미널에서는 계획 모드의 차단이 실제로 강제되지 않아요. Claude는 편집하지 말라고 지시받지만 시도하면 실행될 수 있다는 뜻이에요. 그래서 계획 모드를 안전장치로만 믿으면 안 돼요.

## 직접 해보기

1. 연습용 폴더에서 `claude --permission-mode plan`으로 시작해요.
2. "이 폴더에 README.md를 만들 계획을 세워 줘"라고 시켜요.
3. 계획이 나오면 승인하지 말고 "제목에 이모지는 쓰지 마. 그걸 반영해서 다시 계획해 줘"라고 고치게 해요.
4. 마음에 들면 "승인하고 수정은 하나씩 확인"을 골라 실제로 실행되는 과정을 지켜봐요.

## 오늘 바로 써먹기

- 파일 3개 이상을 건드릴 일은 계획 먼저
- 계획에서 확인할 것: 어떤 파일을 만드나, 근거가 어디서 오나, 내가 시킨 것 말고 더하는 게 있나
- 계획이 모호하면 승인하지 말고 질문하기

## 자주 하는 오해

- "계획 모드는 항상 파일을 못 건드리게 막는다?" 대부분 막지만, 환경에 따라 다를 수 있어요(위 심화 참고).
- "계획을 승인했으니 결과도 맞다?" 승인은 방향을 허락한 것이에요. 결과는 따로 확인해야 해요.
