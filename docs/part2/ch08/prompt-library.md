# 자주 쓰는 질문 모아 두기

<p class="ep-meta"><span>8장 · 8.1</span><span>읽는 시간 약 5분</span><span>2026-11-07</span></p>

!!! abstract "이 페이지에서 배우는 것"
    - 잘 통한 질문은 ==이름을 붙여 모아 두고, 쓸 때마다 조금씩 고쳐 가면== 나만의 도구 상자가 된다.
    - 각 질문 틀에는 "언제 쓰나, 틀, 잘 된 예, 주의할 점"을 같이 적는다.
    - 모아 두기만 하지 말고 가끔 시험해 보고 고친다.

## 1. 요리책 만들기

맛있게 된 요리는 레시피를 적어 두면 다음에 또 만들 수 있어요. 적어 두지 않으면 "그때 뭘 넣었더라?" 하게 되죠.

AI에게 시킨 질문도 마찬가지예요. 2장에서 만든 질문 틀을 **모아 두면** 매번 처음부터 쓰지 않아도 돼요. 그리고 쓰다 보면 점점 나은 버전이 돼요.

!!! tip "10살 눈높이 한 줄 요약"
    잘된 질문은 **요리책에 적어 두세요.** 다음에 또 쓰고, 쓸 때마다 조금씩 고쳐요.

## 2. 한 항목에 적을 것

| 칸 | 적을 것 | 예 |
|---|---|---|
| 이름 | 한눈에 알아볼 이름 | 주간보고 초안 틀 |
| 언제 쓰나 | 이 틀이 맞는 상황 | 매주 금요일, 팀에 보고할 때 |
| 틀 | 빈칸이 있는 질문 본문 | (2장의 질문 틀) |
| 잘 된 예 | 한 번 잘 나왔던 입력과 결과 | 지난주 보고서 |
| 주의할 점 | 이 틀이 잘못되는 곳 | 숫자가 바뀌는지 확인 |
| 고친 날짜 | 언제 마지막으로 고쳤나 | 2026-11-07 |

## 3. 어디에 모을까

- **노트 앱이나 문서 한 장**이면 충분해요. 처음부터 복잡한 도구를 쓸 필요는 없어요.
- **이름 규칙**을 정하세요. "[일] 종류 – 이름"처럼요. 예: "[글] 요약 – 팀장용"
- **항목은 열 개 안팎**으로 시작하세요(이 책의 제안이에요). 많으면 쓰기 어려워져요.
- 서비스에 "내 지침"이나 "프로젝트" 같은 기능이 있다면 자주 쓰는 틀을 거기에 저장할 수도 있어요. (서비스마다 달라요.)

## 4. 시험하고 고치기

Anthropic 문서는 질문(프롬프트)을 다듬는 과정을 이렇게 설명해요. 성공 기준을 정하고, 시험 사례(예외 상황 포함)를 만들고, 질문을 시험하고, 고치는 순환이에요. 성공 기준은 **구체적이고 잴 수 있어야** 한다고 안내해요.

개인이 쓸 때는 이렇게 가볍게 줄일 수 있어요.

1. **성공 기준 한 줄:** "숫자가 하나도 안 틀리고, 5문장 이내"처럼 정해요.
2. **시험 입력 3개:** 평범한 것 2개, 까다로운 것 1개를 정해 둬요.
3. **고칠 때마다 3개로 다시 시험:** 한 곳을 고쳤다가 다른 곳이 나빠지는지 봐요.

!!! note "★ 한 걸음 더 (심화)"
    - 질문 틀은 **모델이 바뀌면 결과도 달라질 수 있어요.** 잘 되던 틀이 어느 날 어긋나면 시험 입력 3개로 다시 확인하세요. Anthropic 문서도 모델이 바뀔 때 평가를 다시 돌리라는 취지의 안내를 해요.
    - 팀에서는 틀 모음을 공유하면 효과가 커요. 다만 모음 안에 개인정보나 기밀이 든 "잘 된 예"를 넣지 않도록 하세요(3장).
    - 이런 시험을 자동으로 돌리는 도구(평가 도구)도 있어요. 개인이 쓰는 질문 틀에는 과할 수 있어요.

## 직접 해보기

1. 이 책에서 만든 질문 틀 중 가장 유용했던 것 3개를 고르세요.
2. 위의 표 칸을 모두 채워서 노트 앱에 저장하세요.
3. 일주일 동안 쓰고, "잘 된 예"와 "주의할 점"에 실제로 겪은 일을 더하세요.

## 오늘 바로 써먹기

1. **세 번 쓴 질문은 저장하세요.** 두 번까지는 직접, 세 번째에 저장해요.
2. **"주의할 점" 칸이 가장 중요해요.** 실수한 경험이 그 칸을 채워요.
3. **성공 기준을 한 줄로 적어 두세요.** "잘 나왔다"의 기준이 있어야 고칠 수 있어요.
4. **한 달에 한 번 정리하세요.** 안 쓰는 건 지우고, 자주 쓰는 건 고쳐요.
5. **공유할 때 개인정보를 지우세요.** "잘 된 예"에 이름이 들어 있지 않은지 보세요.

## 자주 하는 오해

- "틀이 많을수록 좋다" → 많으면 찾기 어려워서 안 써요. 열 개 이내로 시작하세요.
- "한 번 만들면 끝이다" → 모델과 내 일이 바뀌어요. 가끔 시험해야 해요.
- "남이 만든 틀을 가져다 쓰면 된다" → 시작으로는 좋지만 내 일에 맞게 고쳐야 해요.
