# 생각 시간(노력 수준)을 조절하기

!!! abstract "이 페이지에서 배우는 것"
    - 노력 수준(effort)은 ==Claude가 얼마나 오래 생각할지==를 정하는 주 손잡이예요. 프롬프트의 "깊이 생각해"를 대신해요.
    - 단계는 `low`·`medium`·`high`·`xhigh`·`max`이고, 기본은 모델마다 달라요.
    - 높일수록 시간과 토큰이 더 들어요. 필요한 때만 올려요.

## 1. 시험 문제 푸는 시간

쉬운 문제를 오래 붙들면 시간 낭비고, 어려운 문제를 서둘러 풀면 틀려요. 노력 수준이 이 "풀이 시간 손잡이"예요. 공식 문서는 노력 수준을 "Claude가 얼마나 오래 생각할지를 정하는 주된 손잡이"라고 불러요. 생각하는 시간이 길수록 더 많은 경우를 확인하고 답하기 전에 자기 작업을 더 많이 검증해요. 대신 시간과 토큰이 그만큼 더 들어요.

## 2. 단계와 기본값

`/effort`로 바꿔요. 지원 단계는 모델마다 달라요. Opus 5.5, Sonnet 5.5, Haiku 5.5는 `low`, `medium`, `high`, `xhigh`, `max`를 지원하고, 기본은 `medium`이에요. 모델이 지원하지 않는 단계를 고르면 그 아래에서 가장 높은 단계로 내려가요. 이건 2026-11-07의 공식 문서 기준이에요.

| 단계 | 이럴 때 (공식 모범 사례를 쉽게 줄임) |
|---|---|
| `low` | 결과를 매번 내가 확인하며 빠르게 주고받을 때: 아이디어 짜기, 초안, 이름 바꾸기 |
| `medium` | 범위가 분명한 평범한 작업(기본) |
| `high`·`xhigh` | 놓치기 쉬운 경우를 다 찾아야 할 때: 남이 쓴 코드의 버그, 가끔 실패하는 테스트, 읽는 곳을 전부 찾아야 하는 변경 |
| `max` | 혼자 오래 매달려야 하는 아주 어려운 문제. 평범한 일에는 오히려 지나치게 생각해서 `high`보다 나을 게 없을 수 있어요 |

한 번만 깊게 생각하게 하고 싶으면 설정을 바꾸지 않고 그 메시지에 `ultrathink`를 넣을 수 있어요.

## 3. 말투로는 안 바뀌어요

"깊이 생각해", "꼼꼼하게" 같은 말은 마법 단어가 아니에요. 공식 문서는 이런 말이 평범한 글이라서 노력 수준 안에서 조금 밀어 줄 뿐이고, 진짜 손잡이는 노력 수준이라고 말해요. 그러니 생각이 얕다고 느끼면 부탁을 길게 쓰기보다 `/effort`를 올려 보세요.

## 4. 저장 범위

`/effort`로 `low`~`xhigh`를 고르고 `Enter`를 누르면 기본값으로 저장돼요. `s`를 누르면(Claude Code 2.1.257 이상) 이번 대화에서만 적용돼요. `max`는 환경 변수로 정하지 않는 한 이번 대화에만 적용돼요.

!!! tip "10살 눈높이 한 줄 요약"
    쉬운 문제는 빨리, 어려운 문제는 천천히. 풀이 시간 손잡이는 `/effort`예요.

!!! note "★ 한 걸음 더 (심화)"
    노력 수준은 우선순위가 있어요. 환경 변수, 대화 중 고른 것, 시작할 때의 `--effort`, 설정 파일, 모델 기본값 순이에요. 서브에이전트에도 자기 `effort:` 칸이 있어서 조사 조수는 낮게, 검토 조수는 높게 정할 수 있어요(5.8). 그리고 이 설명은 모델이 스스로 "얼마나 생각할지"를 정하는 방식이라는 공식 문서의 설명에 기댄 거예요. 내부가 어떻게 작동하는지는 이 책이 확인하지 않았어요.

## 직접 해보기

1. `/effort`를 입력해 지금 단계를 확인해요.
2. 어려운 문제(예: "이 페이지에서 원본에 없는 주장을 모두 찾아 줘")를 `low`와 `high`로 한 번씩 시켜 봐요. 이번 대화에서만 바꾸려면 `s`를 사용해요.
3. 두 결과의 길이, 찾은 개수, 걸린 시간을 적어서 비교해요.

## 오늘 바로 써먹기

- 빠르게 주고받는 중이면 `low`, 틀리면 안 되는 검토면 `high`
- `max`는 아껴 두기
- 한 번만 깊게: 그 메시지에 `ultrathink`

## 자주 하는 오해

- "높을수록 항상 정확하다?" 평범한 일에서는 시간과 비용만 늘 수 있어요.
- "프롬프트에 '더 열심히'를 쓰면 같은 효과다?" 문서는 그렇지 않다고 해요.
