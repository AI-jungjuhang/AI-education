# 기억 공간은 무엇으로 채워질까

!!! abstract "이 페이지에서 배우는 것"
    - 3부에서 배운 **컨텍스트 창**은 Claude가 지금 대화에서 ==볼 수 있는 모든 것==이 담기는 작업 기억이에요.
    - 내가 한 말만 들어 있는 게 아니에요. 시작할 때 자동으로 올라오는 것, 읽은 파일, 도구 결과도 들어 있어요.
    - `/context`로 내 대화의 기억 공간이 무엇으로 찼는지 직접 볼 수 있어요.

## 1. 책상 위에 올려 둔 것만 볼 수 있어요

3부에서 AI는 대화가 끝나면 아무것도 기억하지 못한다고 배웠어요. 보이는 것은 책상(컨텍스트 창) 위에 올려 둔 것뿐이죠. 그러니 "무엇이 책상 위에 있나"를 알면 AI가 왜 그렇게 행동하는지 보여요. 책상이 가득 차면 새 자료를 올리기 어렵고, 책상이 어지러우면 중요한 자료를 못 찾아요.

## 2. 책상 위에 올라오는 것들

공식 문서는 Claude Code의 책상(컨텍스트 창)에 이런 것들이 들어간다고 설명해요.

| 시점 | 올라오는 것 |
|---|---|
| **내가 아무 말도 하기 전** | CLAUDE.md, 자동 메모, MCP 도구 이름, 스킬 설명 |
| **Claude가 일하는 동안** | 읽은 파일 내용, 파일에 맞춰 자동으로 불러오는 규칙, 훅이 낸 결과 |
| **서브에이전트에게 맡기면** | 큰 파일 읽기는 서브에이전트의 책상에서 일어나고, 요약만 내 책상으로 돌아와요 |

즉 5장에서 만든 스킬이 많을수록, MCP를 많이 연결할수록 "말을 하기도 전에" 책상이 조금씩 차 있어요. 이름과 설명만 올라와서 크지는 않지만, 안 쓰는 도구가 쌓이면 부담이 돼요. 5.10의 플러그인 페이지에서 본 "설치 전에 컨텍스트 비용 확인"이 이 이야기예요.

## 3. 내 대화의 책상 들여다보기

`/context`를 입력하면 지금 책상을 무엇이 얼마나 차지하는지 색칠된 칸으로 보여 줘요. 줄일 수 있는 것에 대한 제안도 나와요. 어떤 CLAUDE.md와 자동 메모 파일이 읽혔는지도 볼 수 있어요. 메모 파일을 고치려면 `/memory`를 써요.

## 4. 책상이 커졌어도

요즘 모델 중에는 100만 토큰의 큰 책상(1M 컨텍스트)을 지원하는 모델이 있다고 공식 문서가 알려 줘요. 책상이 크면 가득 찰 일이 드물지만, **크다고 정리가 필요 없는 것은 아니에요.** 문서도 "작업 사이에 `/clear`는 여전히 할 만하다. 집중된 책상이 더 나은 답을 주고 비용도 덜 든다"고 말해요. 오래된 대화는 매 메시지마다 비용으로 따라오고, 다음에 필요한 파일의 자리를 차지하기 때문이에요.

!!! tip "10살 눈높이 한 줄 요약"
    책상 위에 올라온 것만 AI가 볼 수 있어요. 책상은 크면 좋지만 어질러지면 못 찾아요.

!!! note "★ 한 걸음 더 (심화)"
    책상이 차면 Claude Code는 자동으로 대화를 요약(compact)해서 이어 가요. 이때 무엇이 살아남는지는 다음 페이지에서 표로 봐요. 자동 요약이 시작되는 시점은 모델과 설정마다 달라서, 공식 문서의 "기본 자동 요약 기준" 표를 확인해야 해요. 이 책은 숫자를 옮기지 않아요(바뀌기 쉬워서요).

## 직접 해보기

1. Claude Code를 열고 아무 말도 하기 전에 `/context`를 입력해요. 이미 차 있는 부분이 보일 거예요.
2. 파일을 하나 읽게 시킨 뒤 다시 `/context`를 입력해서 어떤 칸이 늘었는지 비교해요.
3. 5.5~5.7에서 만든 스킬·MCP가 있다면 그것들이 시작할 때 책상의 몇 칸을 차지하는지 찾아봐요.

## 오늘 바로 써먹기

- 답이 흐려지거나 같은 실수를 되풀이하면 `/context`로 책상부터 보기
- 안 쓰는 스킬·MCP·플러그인은 끄거나 지우기
- 긴 읽기는 서브에이전트에게 맡기기. 다만 서브에이전트도 자기 몫의 비용이 든다는 점은 기억해요.

## 자주 하는 오해

- "책상이 크면 아무리 길게 해도 된다?" 길수록 비용이 늘고, 집중도가 떨어질 수 있어요.
- "내가 안 한 말은 책상에 없다?" 아니에요. 시작할 때 올라오는 것들이 있어요.
