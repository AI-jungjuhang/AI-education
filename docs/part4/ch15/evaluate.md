# 평가하고 고치기

<p class="ep-meta"><span>15장 · 15.1</span><span>읽는 시간 약 6분</span><span>2026-11-07</span></p>

!!! abstract "이 페이지에서 배우는 것"
    - "잘 되는 것 같다"는 느낌 대신 ==성공 기준을 정하고, 시험 문제를 만들어 점수를 재서== 고쳐 간다.
    - 시험 문제에는 까다로운 경우도 넣고, 고칠 때는 한 곳씩 바꿔서 다시 잰다.
    - 복잡하게 만드는 것은 점수가 눈에 띄게 좋아질 때만 한다.

## 1. 연습 시험

운동선수는 "잘하는 것 같아"로 대회에 나가지 않아요. 기록을 재고, 약한 부분을 찾아 고치고, 다시 재요. 에이전트와 질문 틀도 마찬가지예요. **재 보지 않으면 좋아졌는지 알 수 없어요.**

!!! tip "10살 눈높이 한 줄 요약"
    **연습 시험을 보고, 틀린 문제를 고치고, 다시 시험을 봐요.** 점수가 올랐는지 숫자로 봐요.

## 2. Anthropic이 말하는 순서

Anthropic의 평가 문서는 프롬프트(질문 틀이나 지시문)를 다듬는 순환을 이렇게 그려요.

1. **성공 기준을 정해요.**
2. **시험 사례를 만들어요.** 예외적인 경우도 잊지 마세요.
3. **처음 질문(프롬프트)을 만들어요.**
4. **시험 사례로 돌려 봐요.**
5. **고쳐요.** 그리고 4번으로.
6. **따로 떼어 둔 시험(홀드아웃)으로 마지막 확인을 해요.**
7. **다듬은 프롬프트를 내보내요.**

좋은 성공 기준은 **구체적**이고 **측정 가능**해야 해요. "성능이 좋다"가 아니라 "감정 분류가 정확하다"처럼요. 숫자 기준이 가장 좋고, 숫자로 하기 어려우면 **일관되게 적용되는 평가 척도**를 써도 돼요. 윤리나 안전처럼 흐릿해 보이는 주제도 "만 번 중 0.1% 미만이 걸러진다"처럼 수치로 만들 수 있다고 문서는 말해요.

## 3. 내가 쓰는 가벼운 평가

개인이나 작은 팀은 이렇게 줄여서 해 보세요.

**① 성공 기준 한 줄:** "고객 문의 10개 중 9개 이상에서 정확한 규정을 인용한다."

**② 시험 문제 10개:** 쉬운 것 6개, 어려운 것 3개, 일부러 이상한 것(규정에 없는 질문, 애매한 질문) 1개. Anthropic 문서의 "예외 상황을 잊지 마라"를 따르는 거예요.

**③ 채점표:** 문제마다 ○/×(또는 3점 척도)로 채점해요. 어디가 틀렸는지 한 줄 메모를 해요.

**④ 틀린 것 모아서 원인 찾기:** 지시문이 모호했나? 자료가 없었나? 도구가 엉뚱한 걸 찾았나?

**⑤ 한 곳만 고치고 다시 재기:** 한 번에 여러 곳을 고치면 무엇이 효과가 있었는지 몰라요.

**⑥ 시험 문제 일부는 숨겨 두기:** 고치면서 시험 문제에만 맞게 되는 것을 막으려고, 2~3개는 고칠 때 보지 않고 마지막에만 써요.

## 4. 점수는 누가 매기나

- **정답이 분명한 일:** 사람이나 간단한 규칙으로 채점해요(숫자가 맞는지, 필요한 단어가 있는지).
- **정답이 애매한 일(글의 품질 등):** 사람이 정해 둔 기준표로 채점해요. Anthropic의 문서는 정확히 일치하는지 보는 방법부터 **AI가 채점하는 방법**까지 다양하게 소개해요.
- AI에게 채점을 맡길 때도 **사람이 일부는 직접 확인**해서 채점이 믿을 만한지 보세요.

!!! note "★ 한 걸음 더 (심화)"
    - 에이전트 설계 글은 "**성능을 재고 구현을 개선하는 것이 핵심**이고, **복잡도는 결과가 눈에 띄게 나아질 때만 더하라**"고 반복해서 말해요(14장). 평가가 그 "눈에 띄게"를 판단하는 도구예요.
    - 도구 설계 글(15.1.2)은 도구의 성능을 평가로 측정하고 Claude Code 같은 에이전트와 함께 도구를 자동으로 개선하는 방법을 소개해요. 이 글과 같은 사이트의 *Demystifying evals for AI agents*(2026-01-09)는 에이전트 평가를 자세히 다루는 것으로 보여요. 이 책에서는 제목과 날짜만 확인했어요.
    - 평가 점수가 곧 진짜 성능은 아니에요. 시험 문제가 실제 일과 다르면 점수만 오를 수 있어요(18장 벤치마크의 함정).

## 직접 해보기

8장에서 저장한 질문 틀(또는 이 장에서 쓴 안내서) 하나로 연습 시험을 만들어 보세요.

| 번호 | 시험 입력 | 기대하는 결과 | 결과 ○/× | 메모 |
|---|---|---|---|---|
| 1 | (쉬운 것) | | | |
| 2 | (쉬운 것) | | | |
| ... | | | | |
| 10 | (일부러 이상한 것) | | | |

1. 틀 그대로 10개를 돌려서 점수를 적어요.
2. 틀린 것에서 가장 많은 원인을 찾아 **한 곳만** 고쳐요.
3. 다시 10개를 돌려서 점수가 올랐는지 확인해요.

## 오늘 바로 써먹기

1. **성공 기준을 한 줄로 쓰세요.** 기준이 없으면 "나아졌다"를 말할 수 없어요.
2. **시험 문제는 10개면 충분해요.** 까다로운 것 하나는 꼭 넣으세요.
3. **한 번에 한 곳만 고치세요.** 그래야 원인을 알아요.
4. **시험 문제 몇 개는 숨겨 두세요.** 고치는 동안 보지 않은 문제로 마지막에 확인하세요.
5. **모델이나 서비스가 바뀌면 다시 재세요.** 같은 시험으로 비교해 보세요(8장).

## 자주 하는 오해

- "몇 번 써 보니 잘 되더라" → 몇 번의 경험은 운일 수 있어요. 같은 시험으로 재세요.
- "시험을 많이 만들수록 좋다" → 처음에는 10개면 충분해요. 중요한 건 까다로운 경우를 넣는 거예요.
- "AI가 채점하니 사람은 안 봐도 된다" → 일부는 직접 확인해야 채점을 믿을 수 있어요.
