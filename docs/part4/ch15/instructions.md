# 좋은 지시문 쓰기

<p class="ep-meta"><span>15장 · 15.1</span><span>읽는 시간 약 6분</span><span>2026-11-07</span></p>

!!! abstract "이 페이지에서 배우는 것"
    - 에이전트의 지시문은 ==새로 들어온 똑똑한 직원에게 주는 업무 안내서==처럼 쓴다.
    - 역할, 목표, 지켜야 할 한계, 도구 쓰는 규칙, 멈추는 조건, 모를 때의 행동을 담는다.
    - 지시문은 동료에게 읽혀 보고 고친다.

## 1. 첫 출근 안내서

새 직원이 들어오면 "이 회사는 뭘 하는 곳이고, 네가 할 일은 이거고, 이런 건 하지 말고, 모르면 이 사람에게 물어봐"라고 알려 주죠. 안내서가 없으면 똑똑한 사람도 엉뚱한 일을 해요.

에이전트도 마찬가지예요. 2장에서 배운 질문 요령이 **길고 오래 일하는 에이전트의 지시문**에서 더 중요해져요. 혼자서 여러 단계를 일하기 때문에 처음 방향이 틀어지면 끝까지 엇나가기 쉬워요.

!!! tip "10살 눈높이 한 줄 요약"
    에이전트에게는 **첫 출근 안내서**를 써 주세요. 안내서가 분명할수록 혼자 일을 잘해요.

## 2. 안내서에 담을 것

Anthropic 문서는 챗봇을 **"똑똑하지만 우리 사정을 모르는 새 직원"**에 비유하고, 요구를 정확히 설명할수록 결과가 좋아진다고 해요. 거기에 에이전트 설계 글의 원칙(단순하게, 계획을 보이게, 종료 조건을 두기)을 더하면 이런 안내서가 돼요.

| 칸 | 쓸 것 | 예 |
|---|---|---|
| 역할 | 누구로서 일하는지 | 우리 동네 도서관의 행사 안내 도우미 |
| 목표 | 무엇을 이루는 일인지, 왜 중요한지 | 이용자가 맞는 행사를 찾도록 돕는다 |
| 쓸 수 있는 도구 | 어떤 도구를 언제 쓰는지 | 행사표 파일을 검색해서 찾는다 |
| 지킬 한계 | 하면 안 되는 일 | 예약, 결제, 개인정보 요구는 하지 않는다 |
| 일하는 순서 | 필요하면 단계별로 | 1) 질문 확인 2) 검색 3) 답변과 근거 제시 |
| 모를 때 | 어떻게 행동할지 | 모르면 모른다고 하고 담당자 연락처를 안내한다 |
| 멈추는 조건 | 언제 끝내거나 사람에게 넘길지 | 두 번 찾아도 없으면 멈추고 사람에게 안내한다 |
| 보고 형식 | 결과를 어떻게 보여 줄지 | 날짜, 장소, 대상 순서의 목록 + 근거 문장 |

## 3. 지시문 예시

```text
너는 우리 동네 도서관의 행사 안내 도우미야.
목표: 이용자가 자기에게 맞는 행사를 찾도록 돕는 거야. 헷갈리는 정보를 주면 이용자가 헛걸음하기 때문에 정확함이 가장 중요해.
도구: 행사표 파일을 검색해서 찾아. 행사표에 없는 내용은 말하지 마.
하지 말 것: 예약이나 결제를 대신 하지 않아. 개인정보를 묻지 않아.
순서: 1) 질문이 어떤 행사를 찾는지 확인해. 모호하면 한 가지만 되물어.
2) 행사표에서 찾아. 3) 날짜, 장소, 대상을 목록으로 알려 주고 근거가 된 행을 보여 줘.
모를 때: "행사표에서 찾을 수 없어요"라고 말하고 도서관 안내 데스크 연락처를 알려 줘.
멈추는 조건: 두 번 찾아도 없으면 더 찾지 말고 위 안내를 해.
```

## 4. 쓰는 요령

- **이유를 붙이세요.** "정확함이 중요해, 헛걸음하기 때문에"처럼 이유를 말하면 비슷한 상황에서도 방향을 맞춰요(2장).
- **순서가 중요하면 번호를 붙이세요.**
- **"하지 마"만 나열하지 말고 "대신 이렇게 해"를 쓰세요.** 막힌 길 옆에 열린 길을 알려 줘요.
- **계획과 판단 과정을 보이게 하세요.** Anthropic의 에이전트 글은 에이전트의 **계획 단계를 명시적으로 보여** 투명성을 높이라고 권해요.
- **단순하게 시작하세요.** 같은 글은 가장 단순한 해법을 먼저 찾으라고 해요. 규칙은 필요할 때 하나씩 늘려요.

!!! note "★ 한 걸음 더 (심화)"
    - 지시문은 에이전트의 컨텍스트 창을 차지해서 매 단계마다 입력으로 들어가요(11장). 너무 길면 중요한 규칙이 묻힐 수 있어요. 가장 중요한 것을 앞과 끝에 두는 것이 좋다는 일반적인 요령이 있어요(6장, 연구는 2023년 모델 기준).
    - 지시문에 있는 규칙은 사용자의 말에 따라 흔들릴 수 있어요. 14장의 Project Vend에서 에이전트가 조르는 말에 할인을 준 것처럼요. 지켜야 할 규칙은 도구의 권한이나 승인 단계로도 **한 번 더** 막는 것이 안전해요.
    - 개발자용 문서에서는 지시문을 시스템 프롬프트에 넣고, 대화마다 바뀌는 정보는 따로 넣는 구조를 써요. 일반 사용자는 서비스의 "사용자 지침"이나 "프로젝트" 기능에 넣는 경우가 많아요(서비스마다 달라요).

## 직접 해보기

내가 AI에게 반복해서 시키는 일(또는 맡기고 싶은 일) 하나로 안내서를 써 보세요.

1. 위 표의 여덟 칸을 채워요.
2. **동료 테스트:** 이 안내서만 읽은 사람이 헷갈릴 부분이 있는지 친구에게 읽혀 보세요. 헷갈려 하면 챗봇도 헷갈려요(2장).
3. 챗봇에게 안내서를 주고 쉬운 질문 하나와 까다로운 질문 하나를 던져서 안내서대로 움직이는지 보세요.

## 오늘 바로 써먹기

1. **역할과 목표와 이유를 첫 세 줄에 쓰세요.** 방향이 맞춰져요.
2. **"모를 때"를 꼭 쓰세요.** 환각과 엉뚱한 추측을 줄이는 중요한 칸이에요.
3. **멈추는 조건을 쓰세요.** 무한히 돌지 않게요.
4. **한계는 대안과 함께 쓰세요.** "하지 마" 옆에 "대신 이렇게"를요.
5. **안내서는 고쳐 가며 쓰세요.** 이상한 행동을 볼 때마다 한 줄씩 추가하고 8장의 틀 모음에 저장하세요.

## 자주 하는 오해

- "지시문이 길수록 에이전트가 잘 따른다" → 길면 중요한 것이 묻혀요. 필요한 것만 쓰세요.
- "한 번 잘 쓰면 모든 상황에서 통한다" → 예상 못 한 상황에서 틀어져요. 시험하며 고치세요.
- "규칙을 써 두면 안전하다" → 말로 쓴 규칙은 흔들릴 수 있어요. 권한과 승인으로도 막으세요.
