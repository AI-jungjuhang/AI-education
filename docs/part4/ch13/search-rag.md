# 검색을 붙이면 달라지는 것

<p class="ep-meta"><span>13장 · 13.1</span><span>읽는 시간 약 6분</span><span>2026-11-07</span></p>

!!! abstract "이 페이지에서 배우는 것"
    - 챗봇에 검색을 붙이면 ==시험 보는 방식이 "암기 시험"에서 "오픈북 시험"으로 바뀐다.==
    - 질문과 가까운 글을 먼저 찾아서 붙여 준 다음 답하게 하는 방식을 **RAG(검색 증강 생성)**라고 부른다.
    - 최신 정보와 출처가 좋아지지만, 찾은 글이 틀리거나 잘못 요약될 수 있다.

## 1. 오픈북 시험

암기 시험은 머릿속에 있는 것만으로 답해야 해요. 기억이 흐릿하면 그럴듯하게 지어내기도 하죠(1장 환각). 오픈북 시험은 교과서를 펴 놓고 **찾아보면서** 답할 수 있어요.

검색을 붙인 챗봇이 오픈북 시험을 보는 챗봇이에요. 질문이 들어오면 먼저 **관련 있는 글을 찾아서** 책상(컨텍스트 창, 11장) 위에 올려놓고, 그 글을 보면서 답해요.

!!! tip "10살 눈높이 한 줄 요약"
    검색을 붙이면 **암기 시험이 오픈북 시험이 돼요.** 찾아보고 답하니까 더 정확해질 수 있지만, 엉뚱한 책을 펼치면 소용없어요.

## 2. 어떻게 작동하나

1. **질문이 들어와요.** "우리 회사 휴가 규정이 어떻게 돼?"
2. **관련 글을 찾아요.** 규정 문서나 웹 페이지에서 질문과 뜻이 가까운 부분을 찾아요. 10장에서 본 "뜻이 가까운 것은 가까이 있다"가 여기에 쓰여요(의미 검색).
3. **찾은 글을 질문과 함께 컨텍스트에 넣어요.**
4. **챗봇이 그 글을 보고 답해요.** 출처를 같이 보여 주는 경우도 많아요.

## 3. 원조 논문이 말한 것

2020년 *Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks*(Lewis 외)는 이 방식에 이름을 붙인 논문이에요. 논문의 문제의식은 이래요. 큰 언어 모델은 사실 지식을 파라미터 안에 저장하지만, **지식에 접근해서 정확하게 다루는 능력은 제한적**이고, 자기 판단의 **근거(출처)를 제시하는 일**과 **세상 지식을 갱신하는 일**은 풀리지 않은 문제라는 거예요. 그래서 모델의 기억(파라미터)에 **바깥 기억(여기서는 위키백과를 벡터로 색인한 것)**을 연결하고, 검색기로 필요한 부분을 찾아 쓰게 했어요. 그 결과 세 가지 열린 질의응답 과제에서 당시 최고 성능을 냈다고 보고했어요.

## 4. 도구를 부르는 방식

검색은 도구의 한 종류예요. Anthropic의 도구 사용 문서는 이렇게 설명해요. 챗봇이 사용자의 요청과 도구의 설명을 보고 **언제 도구를 부를지 스스로 정해요.** 그다음 구조화된 호출 요청을 돌려주고, 그것을 애플리케이션(또는 Anthropic)이 실행해요. 웹 검색 도구의 경우 검색이 실행되고 **출처가 달린 결과**가 답에 포함돼요.

## 5. 달라지는 것과 그대로인 것

| 달라지는 것 | 그대로인 것 |
|---|---|
| 최신 정보를 볼 수 있어요 | 찾은 글이 틀렸다면 답도 틀리기 쉬워요 |
| 출처를 보여 줄 수 있어요 | 출처를 잘못 요약할 수 있어요 |
| 내 문서를 근거로 답해요 | 엉뚱한 글을 찾아오면 엉뚱한 답이 나와요 |
| 학습 시점 이후의 일도 알 수 있어요 | 검색 결과의 순서가 정답의 순서는 아니에요 |

!!! note "★ 한 걸음 더 (심화)"
    - RAG에서는 문서를 작은 조각으로 나눠 각각 벡터로 바꿔 저장해 두고(10장), 질문 벡터와 **가까운 조각**을 찾아와요. 어떻게 나누고 몇 조각을 가져올지가 성능에 크게 영향을 줘요.
    - 검색한 웹 페이지나 문서 안에 "앞의 지시를 무시하고 ~해라" 같은 문장이 숨어 있을 수 있어요(프롬프트 인젝션, 2장). 검색이 붙으면 챗봇이 읽는 글이 내가 쓴 글만이 아니게 되므로 위험이 커져요.
    - 논문은 2020년의 모델과 위키백과로 한 실험이라 요즘 서비스가 어떻게 구현하는지와는 달라요. 요즘 서비스의 검색 방식은 대부분 공개되지 않아요.

## 직접 해보기

검색이 되는 챗봇과 안 되는 챗봇(또는 같은 서비스의 검색 켜기/끄기)이 있다면 비교해 보세요.

```text
이번 주에 나온 소식 중에서 AI와 관련된 큰 소식 하나를 알려 줘. 출처와 날짜도 같이.
```

1. 검색 없이 물었을 때와 검색이 켜졌을 때 답이 어떻게 다른가요?
2. 검색을 켠 답의 출처 링크를 열어서 챗봇이 말한 내용이 실제로 있는지 3장의 방법으로 확인해 보세요.

## 오늘 바로 써먹기

1. **최신 정보는 검색을 켜고 물으세요.** 학습 시점 이후의 일은 일반 답에는 없어요.
2. **"출처와 날짜를 같이"를 요청하세요.** 확인할 길이 생겨요.
3. **출처는 열어서 확인하세요.** 챗봇이 요약한 것이 원문과 같은지 보세요(3장).
4. **검색어에 개인정보를 넣지 마세요.** 질문이 검색 서비스로 전달될 수 있어요(3장).
5. **서로 다른 출처 둘을 요청하세요.** "찬성하는 근거와 반대하는 근거를 각각의 출처와 함께"처럼요.

## 자주 하는 오해

- "검색을 붙이면 환각이 사라진다" → 줄지만 없어지지 않아요. 가져온 글을 잘못 읽을 수도 있어요.
- "출처가 있으면 사실이다" → 출처 자체가 틀렸거나 내용을 잘못 요약했을 수 있어요.
- "RAG는 모델을 다시 학습시키는 것이다" → 학습이 아니라 답할 때 글을 찾아 붙이는 방식이에요. (논문은 파라미터 기억과 바깥 기억을 결합하는 구조를 제안했어요.)
