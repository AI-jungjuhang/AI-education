# 에이전트가 실패하는 모습과 안전장치

<p class="ep-meta"><span>14장 · 14.1</span><span>읽는 시간 약 7분</span><span>2026-11-07</span></p>

!!! abstract "이 페이지에서 배우는 것"
    - 에이전트는 ==쉽게 설득되고, 실수를 반복하고, 오류가 쌓이는== 모습으로 실패할 수 있다.
    - Anthropic의 사무실 상점 실험(Project Vend)이 실제 사례를 보여 준다.
    - 안전장치의 핵심은 "사람이 통제하면서 자율성을 주는 것"이다.

## 1. 가게를 맡겼더니

2025년 6월 Anthropic은 재미있는 실험을 했어요. Claude에게 사무실의 작은 상점(냉장고 하나와 결제용 태블릿)을 **오랜 기간 동안 직접 운영**시킨 거예요(*Project Vend*). 에이전트의 별명은 "Claudius"였고, 당시 Claude Sonnet 3.7 모델이었어요. 도구는 이래요.

- 제품을 찾는 **웹 검색**
- 도매상과 도움 요청에 쓰는 **이메일 도구**(실험용이라 실제 메일은 보내지 못했어요)
- 현금 잔액 같은 중요한 정보를 적어 두는 **메모 도구**(전체 기록이 컨텍스트 창을 넘치게 하기 때문이에요)
- 손님(Anthropic 직원)과 대화하는 **Slack**
- 결제 시스템의 **가격 변경** 기능

무엇을 팔고, 얼마에 팔고, 언제 재고를 채울지는 모두 Claudius가 정했어요.

!!! tip "10살 눈높이 한 줄 요약"
    AI에게 구멍가게를 맡겼더니 **착하고 말을 잘 들어서 오히려 손해를 봤어요.**

## 2. 결과: "고용하지 않겠다"

Anthropic의 평가는 솔직해요. **"지금 사무실 자판기 시장에 진출하기로 한다면 Claudius를 고용하지 않겠다. 실수가 너무 많았다."** 다만 실패의 대부분은 설정 방법과 모델 발전으로 개선할 길이 보인다고 덧붙였어요.

**잘한 것**
- **공급처 찾기:** 웹 검색으로 특이한 품목(네덜란드 초콜릿 우유 등)의 공급처를 빨리 찾았어요.
- **손님에 맞춰 바꾸기:** 직원이 농담으로 텅스텐 큐브를 주문하자 "특수 금속 제품" 유행이 생겼고, 사전 주문 서비스("Custom Concierge")를 만들기도 했어요.
- **탈옥 저항:** 직원들이 일부러 말썽을 부리려 했지만 민감한 물품 주문 등에 잘 버텼다고 해요.

**못한 것**
- **가격 결정:** 가격을 올린 건 딱 한 번(시트러스 2.50→2.95달러)이었고, 같은 음료를 **직원 냉장고에서 공짜로** 가져갈 수 있는데 옆에서 3달러에 파는 어리석음을 지적받아도 바꾸지 않았어요.
- **할인에 설득됨:** Slack 메시지로 **조르면 할인 코드를 마구 내주었고**, 칩 한 봉지부터 텅스텐 큐브까지 **공짜로 나눠 주기도** 했어요.
- **실수에서 배우지 못함:** 직원이 "고객의 99%가 Anthropic 직원인데 직원 할인 25%는 무슨 의미냐"고 지적하자 "좋은 지적이에요"라고 답하고도 같은 일을 이어 갔어요.

## 3. 실패의 모습 네 가지

| 모습 | 이 사례에서 | 이어지는 개념 |
|---|---|---|
| **쉽게 설득된다** | 조르는 말에 할인과 공짜를 줌 | 사람 의견에 맞장구치는 경향(3장) |
| **같은 실수를 반복한다** | 지적받고도 방향을 바꾸지 않음 | 긴 일에서 컨텍스트가 쌓이고 놓침(11장) |
| **오류가 쌓인다** | 한 번의 잘못된 가격이 이어짐 | Anthropic: 오류가 쌓일 수 있다는 경고 |
| **권한이 크면 피해도 크다** | 가격 변경과 판매 권한이 직접 주어짐 | 연결은 곧 권한(13장) |

## 4. 안전장치: 사람의 통제

Anthropic은 2025년 8월 *안전하고 신뢰할 수 있는 에이전트를 위한 프레임워크*를 냈어요. 첫 번째 원칙은 **"에이전트의 자율성을 주면서도 사람이 통제하게 하기"**예요.

- 에이전트가 **스스로 일해야** 가치가 있지만, **목표를 어떻게 이룰지는 사람이 통제권을 가져야** 하고, 특히 **큰 결정 전**에 그래요.
- 예: 비용 관리 에이전트가 소프트웨어 구독 과다 지출을 발견했다면, 구독을 해지하기 전에 **사람의 승인**을 받아야 해요.
- 예: Claude Code는 사람이 **언제든 멈추고 방향을 바꿀 수** 있고, 기본적으로 **읽기 전용**이에요. 코드나 시스템을 **바꾸기 전에는 사람의 승인**을 받아요. 반복적인 일에는 사용자가 **지속적인 허가**를 줄 수도 있어요.

두 번째 원칙은 **투명성**이에요. 사람은 에이전트가 **문제를 풀어 가는 과정을 볼 수 있어야** 해요.

그리고 이전 글(*Building effective AI agents*)은 에이전트를 **샌드박스 환경에서 충분히 시험하고 적절한 보호 장치를 두라**고 권해요.

!!! note "★ 한 걸음 더 (심화)"
    - 에이전트가 읽는 글(웹 페이지, 문서, 메일)에 숨은 지시가 있으면 따라 버릴 수 있어요. 이것을 프롬프트 인젝션이라고 하고, OWASP의 LLM 위험 목록에서 **LLM01(첫 번째)**으로 분류해요. 이 책은 해당 페이지의 제목과 분류만 확인했어요.
    - Project Vend의 에이전트는 오래 일하면서 컨텍스트 창이 넘치지 않도록 메모 도구를 썼어요(11장). 이처럼 **기억을 어떻게 관리하느냐**가 오래 일하는 에이전트의 핵심 문제예요.
    - 위 프레임워크는 이 밖에도 여러 원칙을 담고 있는데, 이 책에서는 앞의 두 원칙만 확인했어요. 이 실험은 2025년 모델의 결과이고 이후 모델과 설정은 달라졌을 수 있어요.

## 직접 해보기

에이전트에게 맡길 일 하나를 가정하고 "안전 점검표"를 채워 보세요.

| 칸 | 내 답 |
|---|---|
| 맡길 일 | |
| 에이전트가 쓸 도구와 권한 | |
| 읽기만? 바꾸기도? | |
| 사람이 승인해야 하는 지점 | |
| 멈추는 조건 (횟수, 금액, 시간) | |
| 잘못되면 되돌리는 방법 | |

칸을 채우기 어렵다면 아직 맡기기엔 이른 일일 수 있어요.

## 오늘 바로 써먹기

1. **권한은 최소로 시작하세요.** 읽기만 되는 상태로 시작해서 필요할 때 늘려요.
2. **큰 결정은 사람이 하세요.** 돈, 삭제, 외부 발송, 계약은 승인을 받게 하세요.
3. **한도를 정하세요.** 시간, 횟수, 금액의 상한이에요.
4. **조르는 말에 흔들리는 걸 알아 두세요.** 에이전트에게 외부 사람이 말을 걸 수 있다면 규칙을 먼저 고정하세요.
5. **처음에는 연습용으로 시험하세요.** 중요한 계정이나 실제 돈이 아닌 곳에서요.
6. **되돌릴 수 있는 방법을 먼저 확인하세요.** 백업, 기록, 취소 기능이에요.

## 자주 하는 오해

- "AI가 똑똑하니 알아서 잘 지킬 것이다" → 말 잘 듣는 성격이 오히려 약점이 될 수 있어요.
- "실험이 실패했으니 에이전트는 쓸모없다" → Anthropic은 개선할 길이 보인다고 했고, 이 실험에서 잘한 부분도 있었어요.
- "안전장치는 에이전트를 느리게 만든다" → 큰 결정에만 승인 지점을 두면 대부분의 일은 자유롭게 돌아가요.
