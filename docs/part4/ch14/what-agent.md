# 에이전트란 무엇일까

<p class="ep-meta"><span>14장 · 14.1</span><span>읽는 시간 약 6분</span><span>2026-11-07</span></p>

!!! abstract "이 페이지에서 배우는 것"
    - **에이전트**는 =="스스로 방법을 정하고, 도구를 쓰고, 결과를 보며 계속 일하는 AI"==다.
    - 정해진 순서대로만 움직이는 **워크플로**와는 누가 순서를 정하느냐가 다르다.
    - 에이전트는 비용이 크고 실수가 쌓일 수 있어서, 꼭 필요할 때만 쓰는 것이 권장된다.

## 1. 요리 설명서와 요리사

요리 설명서에는 "1. 양파를 썬다 2. 볶는다 3. 소금을 넣는다"처럼 순서가 정해져 있어요. 설명서를 따르는 사람은 순서를 고민하지 않아도 돼요. 반면 "손님에게 맛있는 저녁을 차려 줘"라는 말만 들은 요리사는 냉장고를 열어 보고, 뭐가 있는지 보고, 무엇을 만들지 **스스로 정해야** 해요.

앞의 것이 **워크플로**, 뒤의 것이 **에이전트**예요.

!!! tip "10살 눈높이 한 줄 요약"
    워크플로는 **설명서를 따르는 로봇**, 에이전트는 **냉장고를 열어 보고 스스로 메뉴를 정하는 요리사**예요.

## 2. Anthropic이 나눈 기준

Anthropic이 2024년 12월에 낸 글 *Building effective agents*는 이렇게 구분해요.

- **워크플로(workflows):** 언어 모델과 도구가 **미리 정해 둔 코드의 경로**를 따라 움직이는 시스템이에요.
- **에이전트(agents):** 언어 모델이 **스스로 자기 과정과 도구 사용을 이끄는** 시스템이에요. 일을 어떻게 해낼지 통제권을 모델이 가져요.

글은 에이전트의 작동을 이렇게 묘사해요. 사람의 명령이나 대화로 시작하고, 일이 분명해지면 **스스로 계획하고 독립적으로** 움직여요. 매 단계에서 도구 호출 결과나 코드 실행 결과 같은 **환경의 반응을 받아** 진행 상황을 판단해요. 필요하면 **중간 점검 지점이나 막혔을 때 사람의 의견을 구하며 멈출 수 있어요.** 일이 끝나면 종료하지만, **최대 반복 횟수 같은 종료 조건**을 두는 것도 흔하다고 해요. 그리고 이렇게 말해요: 에이전트는 복잡한 일을 다루지만 구현은 단순한 경우가 많아요. 보통 **"환경의 반응을 받아 도구를 쓰는 언어 모델이 반복문 안에서 도는 것"**일 뿐이에요.

## 3. 언제 쓰고 언제 쓰지 말까

글의 조언은 의외로 신중해요.

- **가능한 가장 단순한 해법을 찾고, 필요할 때만 복잡하게 만드세요.** 에이전트 시스템을 아예 만들지 않는 것이 답일 수도 있어요.
- 에이전트 시스템은 대개 **속도와 비용을 내주고 더 나은 성능을 사요.** 그 거래가 맞는지 따져야 해요.
- 많은 경우 한 번의 호출을 **검색과 예시로 다듬는 정도**면 충분해요.
- 에이전트는 **단계 수를 미리 알 수 없고 고정된 경로를 짤 수 없는 열린 문제**에 알맞아요. 대신 **비용이 커지고 오류가 쌓일 가능성**이 있어서, 샌드박스 환경에서 충분히 시험하고 보호 장치를 두라고 권해요.

!!! warning "알려 드려요"
    이 글에는 "여기서 설명한 도구 환경의 상당 부분이 2024년 12월 이후 바뀌었다"는 주의 문구가 붙어 있어요. 구체적인 도구 이름보다 **구분 기준과 원칙**을 기억하세요.

## 4. 우리 곁의 에이전트

글이 드는 예는 **코딩 에이전트**(여러 파일을 고쳐야 하는 일을 설명만 보고 해내는 것)와 **컴퓨터 사용(computer use)**(AI가 컴퓨터를 직접 써서 일을 하는 것)이에요. 이런 도구들은 파일을 읽고, 코드를 고치고, 실행해 보고, 결과를 보며 다음 행동을 정해요.

!!! note "★ 한 걸음 더 (심화)"
    - 글은 세 가지 원칙을 말해요. 에이전트의 **설계를 단순하게 유지하기**, 에이전트의 **계획 단계를 명시적으로 보여서 투명성을 우선하기**, 에이전트와 도구 사이의 접점(ACI)을 **도구 설명과 시험으로 정성껏 만들기**예요.
    - 에이전트는 12장에서 본 "한 토큰씩 이어 쓰기"가 **밖으로 한 겹 더 반복**되는 모습으로 볼 수 있어요. 글을 쓰는 반복 안에서 도구를 부르는 반복이 또 일어나요.
    - 이 책에서 읽은 글은 2024년 12월 것이고, 에이전트 분야는 빠르게 변해요. 최신 접근은 Anthropic의 후속 글과 문서를 보세요.

## 직접 해보기

최근에 AI에게 시킨 일 세 가지를 떠올려서 분류해 보세요.

| 일 | 순서가 정해져 있었나? | 도구를 썼나? | 스스로 판단해야 했나? |
|---|---|---|---|
| | | | |

- 순서가 정해져 있고 판단이 필요 없는 일이면 "그냥 질문"이나 "워크플로"로 충분해요.
- 순서를 미리 알 수 없고 도구를 여러 번 써야 하는 일이 "에이전트가 필요한 일"이에요.

## 오늘 바로 써먹기

1. **먼저 가장 단순한 방법을 쓰세요.** 한 번의 질문으로 되는 일에 에이전트는 과해요.
2. **순서가 정해진 일은 단계로 나눠 맡기세요.** 2장의 "한 번에 하나씩"이에요.
3. **에이전트에게 일을 맡길 때 중단 조건을 정하세요.** "10단계 안에", "여기까지 하고 보고해" 같은 한도예요.
4. **중간 점검 지점을 만드세요.** "계획을 먼저 보여 주고, 내가 승인하면 실행해"가 대표적이에요.
5. **처음에는 지켜보는 환경에서 시험하세요.** 중요한 계정이나 파일이 아니라 연습용으로요.

## 자주 하는 오해

- "에이전트가 일반 챗봇보다 항상 낫다" → 비용과 오류 위험이 커서, 단순한 일에는 과해요.
- "에이전트는 완전히 새로운 AI다" → 글에 따르면 도구를 쓰는 언어 모델이 반복문 안에서 도는 것이에요.
- "에이전트가 알아서 하니 지켜볼 필요가 없다" → 오류가 쌓일 수 있어서 점검이 필요해요.
